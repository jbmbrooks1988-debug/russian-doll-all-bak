# File-Op Plan: Reusable File Management for TPMOS

## 1. Concept: "Trait Menus" (Reusable Sub-Apps)
This plan implements the "File Menu" as a **Trait Menu**. A Trait Menu is a standardized set of methods (defined in PDL) and a corresponding layout (`.chtpm`) that can be included in any project to provide consistent system-level functionality.

## 2. Objectives
Add a "File" menu to `fuzz-op` (via Xlector) that allows:
- **New**: Resets the current map and variables.
- **Save**: Saves the current map/variables to a named slot in the user's folder.
- **Save-As**: Saves the current state to a *newly named* slot (requires user input).
- **Load**: Lists and loads previously saved states from the user's folder.

## 3. Storage Architecture
Data will be stored in:
`projects/user/pieces/profiles/<username>/saves/<project_id>/<slot_name>/`
- `state.txt`: Variables (hunger, energy, turn, etc.)
- `map_01.txt`: The world map data.

## 4. Components

### A. The File Layout (`projects/fuzz-op/layouts/file_menu.chtpm`)
A dedicated sub-layout for file operations.
- Displays current "Project Name" and "Active User".
- Buttons: `[1] New`, `[2] Save`, `[3] Save-As`, `[4] Load`, `[9] Back`.
- Includes a `<cli_io>` field for naming "Save-As" targets.

### B. The Ops (`projects/fuzz-op/ops/`)
1. **`file_new_op.+x`**: Wipes active state and loads defaults.
2. **`file_save_op.+x`**: Copies current `pieces/` state to the user's active save slot.
3. **`file_save_as_op.+x`**: Takes `<name>` from CLI input and creates a new save directory.
4. **`file_load_op.+x`**: Lists directories in `saves/` and updates current `pieces/` with selected data.

### C. PDL Integration (`projects/fuzz-op/pieces/xlector/piece.pdl`)
Add the "File" method:
- `METHOD | file | projects/fuzz-op/ops/+x/open_file_menu_op.+x`

### D. Open File Menu Op (`projects/fuzz-op/ops/open_file_menu_op.c`)
- Changes `active_layout_id` to `file_menu` in `pieces/apps/player_app/manager/state.txt`.
- Pulses `state_changed.txt`.

## 5. Reusability Strategy
To make this reusable for other projects:
1. **Generic Ops**: Design the ops in `projects/user/ops/` instead of `fuzz-op/ops/` so they can be installed via Fondu.
2. **Path Parameterization**: Ops will take `source_project_id` and `target_save_name` as arguments.
3. **Standard Layout**: Move `file_menu.chtpm` to `projects/user/layouts/` so it can be `href`'d by any app.

## 6. Implementation Steps
1. Create `file_menu.chtpm` in `projects/user/layouts/`.
2. Implement `file_save_op.c`, `file_load_op.c`, etc. in `projects/user/ops/`.
3. Update `fuzz-op` Xlector PDL to include the `file` method.
4. Create the `open_file_menu_op` to bridge the project to the user file menu.

## 7. Verification
1. Open `fuzz-op`.
2. Select Xlector -> File.
3. Verify "File Menu" layout loads.
4. Perform "Save-As" with name "test_v1".
5. Verify files exist in `projects/user/pieces/profiles/<user>/saves/fuzz-op/test_v1/`.
6. Modify game state (e.g., move pet).
7. Perform "Load" of "test_v1".
8. Verify state reverts to original "test_v1" values.

## 8. Future Expansion
Once the implementation is verified and proven successful in `fuzz-op`, the same "File Menu" Trait will be integrated into the `op-ed` project to provide consistent world-building state management.

Subsequently, the system will be expanded to support the 3D counterparts of these projects (`fuzz-op-gl`, `op-ed-gl`) and the `piececraft-3d` engine, ensuring a unified cross-theater file management experience (ASCII/GL).
