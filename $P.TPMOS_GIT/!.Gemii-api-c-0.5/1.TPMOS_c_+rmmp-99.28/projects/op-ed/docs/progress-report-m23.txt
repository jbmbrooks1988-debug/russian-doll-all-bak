# Progress Report (m23) - Topology Audit
**Date:** 2026-05-23
**Project:** op-ed / TPMOS
**Status:** TOPOLOGY ALERT (Deprecated Structures Detected)

## 1. Context: The `apps/` vs `ops/` Divergence
Per `!.TPMOS_ONBORD_BIBLE_2.md` (v1.0), the `pieces/apps/` directory is a **deprecated residual structure**. The canonical TPMOS topology mandates that all system tools and "muscles" reside in `pieces/ops/`.

## 2. Identified Misuse
During the initial implementation of the `op-ed` Player and Mirror Lab, several legacy paths were incorrectly referenced or maintained:
- **`pieces/apps/playrm/ops/`**: This directory contains critical "Muscles" (e.g., `move_entity`, `render_map`) that should be migrated to `pieces/ops/`.
- **`pieces/apps/player_app/`**: This structure is acting as a monolithic manager/buffer holder, which violates the "Thin Module" and "Sovereign Handover" principles.
- **`projects/op-ed/player/manager/player_bootstrap.c`**: Currently points to `pieces/system/prisc/prisc+x` (correct) but my previous plan mentioned using `pieces/apps/playrm/` for logic, which is deprecated.

## 3. Corrective Strategy: The Migration to Canonical TPMOS
To align with the Onboarding Bible, we must perform the following "Topology Normalization":

### A. Muscle Migration (Immediate)
- We will relocate (or symlink for legacy support) the binaries in `pieces/apps/playrm/ops/+x/` to `pieces/ops/play-ops/+x/`.
- **Reason:** This ensures the Player and Editor are calling "Global Ops" rather than project-specific "App Ops."

### B. Player Decoupling
- The `op-ed` Player will NOT use `pieces/apps/player_app/`.
- It will be a sovereign project in `projects/op-ed/player/` and utilize the `pieces/os/` directory for transient streams like `history.txt`.
- **Reason:** To prevent "App Layout project_id Drift" and ensure a clean export package.

### C. Sovereign Handshake Verification
- All project state changes (e.g., map switching) must write directly to `projects/op-ed/games/[PROJECT]/project.pdl`.
- The Manager and Player must only read from this sovereign source, never from a shared "App State."

## 4. Updated Goal for Slice 1 & 2
- **Slice 1 (Normalized):** Initialize `fuzz-op-mirror` and verify it contains its own `pieces/` and `maps/` in the new canonical structure.
- **Slice 2 (Normalized):** Compile the `player_bootstrap.+x` to call the new canonical `pieces/ops/` muscles.

**Summary:** We have identified the topology drift and are pivoting to a 100% "Ops-based" model. The "Apps" folder will be treated as legacy debt to be phased out as we move toward the "Thin Engine" vision.
