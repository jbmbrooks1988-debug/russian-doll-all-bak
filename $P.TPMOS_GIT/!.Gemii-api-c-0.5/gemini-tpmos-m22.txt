## 1. Credential Geography (Geography is Destiny)
Following the standard that "If it's not in a file, it's a lie," we will establish a canonical location for the Gemini API Key. This prevents hardcoding and ensures the credential survives project resets.

- **Path:** `pieces/os/credentials/gemini_api_key.txt`
- **Format:** Atomic text file containing only the API key.
- **Access:** The Manager will resolve this path relative to `project_root` or use the `pieces/locations/location_kvp` discovery mechanism.

## 2. API Selection & Theater Integration
The `groq-ollama` manager uses a projection-based UI. We will integrate Gemini as a native option.

- **Config Update:** Append `Gemini|https://generativelanguage.googleapis.com` to `projects/groq-ollama/config/apis.txt`.
- **UI Refresh:** The `load_apis()` and `update_menu_markup()` functions in the manager will automatically project this as a button in the `groq-ollama_api_menu` field within `gui_state.txt`.

## 3. Manager Logic Refactoring (The Brain)
We will modify `groq-ollama_manager.c` to handle the specific requirements of the Google Gemini REST API.

- **Detection:** Add `is_gemini` boolean flag, triggered when `g_api_url` contains `googleapis.com`.
- **Model Resolution:** Fix `resolve_local_model()` to detect Gemini and default to `gemini-1.5-flash` instead of querying Ollama's tags.
- **Key Retrieval:** Prioritize `getenv("GEMINI_API_KEY")` as per the security mandate to avoid blacklisting.
- **Payload Construction:** 
    - Deploy `gemini_payload_builder` as a project Op in `projects/groq-ollama/ops/+x/`.
    - This tool converts TPMOS `context.json` into Gemini's `contents` structure.
- **Streaming Execution:**
    - Use `streamGenerateContent?alt=sse`.
    - The child process handles the SSE stream and writes deltas to `state/stream_resp.txt`.
    - **Fix:** Uses a robust search for `"text"` (ignoring spacing) to ensure all LLM deltas are captured.
    - **Fix:** Redirects `stderr` to `stdout` (`2>&1`) to capture and log API errors in `state/gemini_stream.log`.
- **Response Handover:**
    - The child process writes a flattened JSON to `tmp_llm` upon stream completion.
    - **Fallback:** If final JSON parsing fails, the parent manager falls back to unescaping and displaying the content of `state/stream_resp.txt`.
- **CPU Safety:** Maintain the `fork()/exec()` pattern. No `system()` calls.

## 4. Response & Tool Parsing (The Ops)
- **JSON Parsing:** The `json_parser` Op is used to extract `text` and `functionCall`.
- **Fix:** Ensure the consolidated JSON in `tmp_llm` uses a structure that `json_parser` can reliably traverse (shallow keys preferred).
