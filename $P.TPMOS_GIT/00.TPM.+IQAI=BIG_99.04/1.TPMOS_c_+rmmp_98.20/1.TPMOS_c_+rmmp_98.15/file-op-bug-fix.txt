# File-Op Bug Fix Report

## 1. Observed Issues

### A. Index Shifting (The "Vanishing Button" Trap)
In the frames provided, the "Save" button is Index 4, but the manager was often looking for a hardcoded numeric key. 
- **The Bug**: If `slot_1_exists` is false, the 2nd slot button disappears. This causes all buttons below it to "shift up" by one index. 
- **Result**: The "Save As" button (visual #5) becomes Index 4. The manager then executes the "Save" logic (which overwrites "default") instead of the "Save As" logic. This is why "Save As" appeared to fail—it was actually doing a standard "Save".

### B. Ugly Button Nesting
The UI shows: `10. [ ] 2. [default]`.
- **Cause**: The manager was manually adding "10." as text, and then the parser was adding "[ ] 2." as the interactive indicator for the button.

### E. Keyboard Shortcut Failure
The manager currently ignores keyboard input.
- **Cause**: I refactored the `main` loop to search for `COMMAND: ` strings (generated by mouse clicks). However, pressing a key on the keyboard writes a raw ASCII code (e.g., `51` for '3').
- **The Bug**: Since the manager no longer has a numeric key listener, keyboard shortcuts like `3` for New do absolutely nothing.

## 2. Proposed Fixes (Final)

1.  **Hybrid Input Listener**: Update `file_manager.c` to handle both `COMMAND: ` strings AND raw numeric keys.
2.  **Fixed Action Indices**: Move the "Actions" (New, Save, Save-As, Load, Delete) to the TOP of the layout. This ensures they always occupy Indices 1-5, regardless of how many save slots exist.
3.  **Command-Key Mapping**: In `route_input`, map the fixed keys (1-5) directly to the string commands (FILE:NEW, etc.).
4.  **Clean Layout**: Remove the `[ ]` text wrappers—the parser adds those automatically.

## 3. Final Action Plan
- Move buttons to the top of `file_menu.chtpm`.
- Restore the numeric key listener to `file_manager.c`.
- Synchronize indices 1-5 with the core actions.
