# P2P-NET Restoration Summary (May 11, 2026)

## Overview
The `p2p-net` project has been successfully restored to a clean, functional state following the core CHTPM refactor. All improper hardcoding has been removed from the parser, and the project's internal manager has been empowered to handle its own state.

## Key Changes
1.  **Parser Decoupling:** Removed `load_p2p_dashboard_state` from `chtpm_parser.c`. The parser now purely follows the "Dumb Theater" model, loading state only from standard `gui_state.txt` files.
2.  **Manager Upgrade:** Refactored `p2p_manager.c` to:
    -   Auto-detect local IP address.
    -   Identify active subnet ports.
    -   Display local user info ("Self") as the first entry in the peer list.
    -   Scan the `pieces/` directory for subnets, neighbors, and messages.
3.  **Data Cleanup:** Cleared all stale mock data from `pieces/network/` and `pieces/chat/inbox/`. The dashboard now correctly shows only real local information until discovery operations are performed.
4.  **Path Resilience:** Added environment-aware path resolution to ensure the manager functions correctly across different terminal setups.

## Current Dashboard Basics
- **Account:** Displays current wallet address.
- **Wallets:** Cycles through local inbox directories.
- **Subnets:** Shows discovered/configured subnets with the active one bracketed.
- **Peers:** Always shows `Self@<IP>:<PORT>` first, followed by discovered neighbors.
- **Actions:** Basic ops (Compose, Check, Join, Leave, Switch) are mapped to keys 1-7.
- **Debug-Append (Key 8):** Forks a real background agent (`debug_peer_agent`) that registers as a peer and sends a timestamped email heartbeat every 10 seconds.

## Status: FUNCTIONAL RESTORED
The project is ready for real local network testing via the `broadcast_join` and `send_message` ops.
