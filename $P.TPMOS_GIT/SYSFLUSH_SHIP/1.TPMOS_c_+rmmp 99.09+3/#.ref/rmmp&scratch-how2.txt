# Integration Guide: Scratch Blocks & RPG Maker Events in op-ed
**Version:** 1.0 (May 17, 2026)
**Purpose:** Mapping visual scripting concepts to TPMOS PAL Orchestration.

## 1. Scratch Block Mapping (Motion & Control)
In `op-ed`, Scratch-style blocks are the primary way to define piece-level logic.

| Scratch Block | op-ed / PAL Implementation |
| :--- | :--- |
| **When Green Flag Clicked** | `METHOD | on_load` in `piece.pdl` -> points to a start script. |
| **Forever** | PAL `loop:` label with an unconditional `JMP loop` at the end. |
| **If [ ] Then** | PAL `CMP <var>, <val>` followed by `JE` (Jump if Equal) or `JNE`. |
| **Move [10] Steps** | Call to `pieces/apps/playrm/ops/+x/move_entity.+x` with distance params. |
| **Go to x: [ ] y: [ ]** | Direct write to `state.txt`: `pos_x=[x]`, `pos_y=[y]`. |
| **Wait [1] Seconds** | PAL `SLEEP 1000` (ms) or calling a timer Op. |
| **Broadcast [Message]** | Writing a signal to `pieces/apps/player_app/events.txt` for global capture. |

## 2. RPG Maker Event Command Mapping (Flow & World)
RPG Maker commands focus on high-level game progression and UI.

### A. Message & Dialogue
- **Show Text...**: Translated to `CALL pieces/apps/playrm/ops/+x/console_print.+x "Your message here"`.
- **Show Choices...**: Launches a sub-layout with `<button>` elements, each injecting a specific KEY.

### B. Game Progression (Switches & Variables)
- **Control Switches/Variables**: In TPMOS, everything is a piece state. "Switches" are just boolean entries in `projects/<id>/pieces/global_vars/state.txt`.
- **Self Switch**: Entries inside a piece's own `state.txt` (e.g., `chest_opened=1`).

### C. Flow Control
- **Label / Jump to Label**: Native PAL labels (`label:`) and `JMP` commands.
- **Common Event**: A shared `.asm` script in `projects/<id>/scripts/common/` that multiple pieces can `CALL`.

## 3. Incorporation into op-ed
The `EVENT` menu in the editor provides a visual grid of these commands.
1. **Selection**: User clicks a "Block" (e.g., [CHANGE HP]).
2. **Parameters**: A `<cli_io>` or popup menu appears to set the value (e.g., -10).
3. **ASM Generation**: The manager appends the corresponding PAL instruction to the active `.asm` buffer.
   - Example: User adds [CHANGE HP -10] -> Manager writes `SUB hp, 10` to the script.
4. **Binding**: The user chooses which trigger (interact, touch, on_load) executes this script.
