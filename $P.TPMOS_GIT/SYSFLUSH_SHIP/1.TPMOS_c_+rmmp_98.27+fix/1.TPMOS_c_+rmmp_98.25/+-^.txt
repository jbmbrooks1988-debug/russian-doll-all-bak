# +-^ Project Demo: Activation Submenu Implementation Plan

We are adding a new design option for hierarchical menus called "Activation Submenus". 
This feature allows a menu to be "activated" (getting the `[^]` marker), which then:
1. Resets item numbering to 1 for its children.
2. Disables index-jumping for any elements outside the active menu.
3. Restricts navigation (arrow keys) to the active menu's children.

## Changes Required

### 1. CHTPM Parser (`pieces/chtpm/plugins/chtpm_parser.c`)
- **`is_navigable(idx)`**: Update to return `false` for any element that is not a descendant of `active_index` (when `active_index` is a menu).
- **`render_element()`**: 
    - Reset `p_current_interactive` counter when entering the active menu's branch.
    - Only increment and display numbers for elements that are currently `is_navigable()`.
- **`process_key()`**:
    - Add logic to the "Active mode" block to handle `ARROW_UP/DOWN`, `isdigit` (jumping), and `ENTER` for descendants.
    - Add `ACTIVATE` command to `onClick` handling to set `active_index` and focus the first child.

### 2. Demo Layout (`projects/+-demo/layouts/+-demo.chtpm`)
Add an "Activation Menu" example at the bottom:
```xml
<button label="[Menu A][+] (Press Enter to Activate)" onClick="ACTIVATE" id="menu_a">
    <br/>
    <button label="Sub-item 1" onClick="KEY:1" id="sub1" /><br/>
    <button label="Sub-item 2" onClick="KEY:2" id="sub2" /><br/>
</button>
```

## How to Test
1. Compile the updated parser.
2. Load the `+-demo` project.
3. Navigate to "Menu A" and press Enter.
4. Observe that the marker changes to `[^]` and sub-items are numbered 1 and 2.
5. Try jumping to a main-level number (e.g., "1" for Dir1) and verify it doesn't work while Menu A is active.
6. Press ESC to return to global navigation.
