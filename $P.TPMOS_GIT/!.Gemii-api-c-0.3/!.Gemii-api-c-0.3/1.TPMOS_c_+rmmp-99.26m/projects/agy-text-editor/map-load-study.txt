# Map Load Study: op-ed vs agy-text-editor
**Date:** 2026-05-22

## 1. op-ed Load Pipeline (WORKING)
The `op-ed` manager uses a multi-stage synchronization process when loading a project or map:

1. **Trigger:** `SET_PROJECT:name` command.
2. **State Update:**
    - Sets `current_project`.
    - `load_project_metadata()`: Reads `project.pdl`.
    - `scan_maps()`: Refreshes the `project_maps` array from the filesystem.
    - Sets `map_idx` and `stage_map_idx`.
3. **Synchronization:**
    - `sync_current_map()`: Explicitly writes `current_map=...` to `pieces/apps/player_app/manager/state.txt`.
    - `update_current_map_dir()`: Derives directory names for relative pathing.
    - `sync_system_project_id()`: Writes `project_id=...` to `pieces/apps/player_app/manager/state.txt`.
4. **UI Transition:**
    - Appends to `pieces/display/layout_changed.txt` to switch back to the editor layout.
5. **Render Trigger:**
    - `trigger_render()`: Calls an external script `render_map.+x`.
    - `hit_frame_marker()`: Appends "M" to `pieces/display/frame_changed.txt`.

## 2. agy-text-editor Load Pipeline (BROKEN)
The current `agy-text-editor` load pipeline is more direct but lacks certain synchronization steps:

1. **Trigger:** `LOAD_FILE:path` or `LOAD_ACTION`.
2. **State Update:**
    - `load_from_path(rel_path)`:
        - Resolves full path (was broken due to `project_root` mismatch).
        - Copies file to `projects/agy-text-editor/pieces/document.txt` (the working buffer).
        - Sets `active_file_path`.
        - Calls `load_document_to_buffer()`: Reads `document.txt` into memory lines.
        - Resets `cursor_x`, `cursor_y`.
3. **UI Update:**
    - `update_gui_state()`: Rebuilds `editor_map` markup and writes to `gui_state.txt`.
    - Writes `project_id=agy-text-editor` to `pieces/apps/player_app/manager/state.txt`.
4. **Render Trigger:**
    - `trigger_render()`: Hits both `frame_changed.txt` and `state_changed.txt`.

## 3. Identified Gaps & Differences
- **Working Buffer vs. Direct Load:** `agy-text-editor` uses a staging file (`document.txt`), whereas `op-ed` seems to load metadata and then sync the state for the Parser to handle.
- **Explicit Metadata Loading:** `op-ed` calls `load_project_metadata()` which reads a PDL. `agy-text-editor` doesn't have a PDL for the loaded file (since it's a raw text editor).
- **Clobbering:** `agy-text-editor` uses `cli_io` in the file browser. The project plan suspects the Parser's `cli_io` sync clobbers `gui_state.txt`. `op-ed` doesn't use `cli_io` in its browser; it uses buttons with `onClick="SET_PROJECT:..."`.
- **Project Root:** `agy-text-editor` had a hardcoded/broken `project_root` in `location_kvp` resolution. (FIXED in research phase).

## 4. Proposed Solution Pattern
To fix the `LOAD_FILE` bug in `agy-text-editor`:
1. **Bypass cli_io clobbering:** Instead of relying on the `file_path_input` field for the action, ensure the `LOAD_FILE` command (from the button click) is handled completely by the Manager, and that the Manager wins the write race by triggering a full render *after* the state is stable.
2. **Force-Sync active_project:** Explicitly write the `active_project` to `pieces/apps/player_app/manager/state.txt` so the Parser knows the "Sovereign" state has changed.
3. **Layout Transition:** After a successful `LOAD_FILE`, transition back to `editor.chtpm` automatically, similar to how `op-ed` transitions back to its main layout.
