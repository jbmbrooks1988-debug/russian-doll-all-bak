# May 17 Plan: CHTPM Selection-Based File & Project Management

## 1. Goal
Upgrade the CHTPM project and file management to be purely selection-based (using dynamic buttons) instead of manual text input, ensuring proper UI alignment within standard box layouts.

## 2. Updated Strategy: Selection-First UI
We are moving away from `<cli_io>` for slot names and horizontal scrollers for projects.

### Phase 1: Parser Infrastructure
- **Generic Command Support**: Updated `chtpm_parser.c` to support `SET_` and `OP:` prefixes in `onClick`. These are injected into `history.txt` as `COMMAND: <cmd>`, allowing managers to handle them as strings.

### Phase 2: Manager Logic (`op-ed_manager.c`)
- **Markup Generators**: Added `build_project_markup()` and `build_slot_markup()` to generate vertical button lists wrapped in `║  ` and ` ║` for perfect box alignment.
- **Command Handling**: Added `handle_command()` to process `SET_PROJECT:<name>` and `SET_SLOT:<name>` from the input history.
- **Slot Discovery**: Updated `write_gui_state()` to publish `slot_selection_markup` by scanning the user's save directory.

### Phase 3: Layout Standardization
- **`file_menu.chtpm`**: Proper menu box. Replaced `slot_name` input with a "BROWSE SLOTS" button.
- **`load_menu.chtpm`**: Vertical project list using `${project_selection_markup}`.
- **`load_slot.chtpm`**: New layout to browse and select save slots for the current project.

### Phase 4: Backend Ops
- **`file_op.c`**: Added `list` command to return CHTPM button markup for available slots.

## 3. Verification
- Open File Menu: Verify it's a clean box with vertical buttons.
- Click "PROJECT LOADER": Verify project list is vertical, selectable, and loads the project into the editor.
- Click "BROWSE SLOTS": Verify it shows a list of existing slots for the project and clicking one loads it.
