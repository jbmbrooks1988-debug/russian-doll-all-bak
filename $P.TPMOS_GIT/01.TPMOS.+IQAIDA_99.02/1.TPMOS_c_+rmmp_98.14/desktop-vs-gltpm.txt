# ARCHITECTURAL REPORT: GL-OS Desktop vs. GLTPM Apps
Date: 2026-05-03
Status: ANALYSIS OF DUPLICATE APP SETS

## 1. Executive Summary
The GL-OS environment currently contains two distinct methods for launching projects: the **"Desktop Apps"** menu and the **"GLTPM Apps"** menu. This overlap is a direct consequence of the "From Scratch" development process, where early Proof-of-Concept (POC) features coexist with newer, standardized layout systems.

## 2. The Two Systems Explained

### A. The "Desktop" System (Legacy/Hardcoded)
- **Mechanism**: `create_mirrored_window()`
- **Logic**: This system uses hardcoded logic inside `gl_desktop.c`. It manually populates menus (e.g., "scan", "collect", "place") and uses a generic grid renderer.
- **Project Status**: `fuzz-op-gl` still uses this when launched from the Desktop menu, which is why it looks like a simplified "POC" version.
- **The Exception**: `piececraft-3d` was recently patched to use the modern system even when clicked from the Desktop menu.

### B. The "GLTPM" System (Modern/Sovereign)
- **Mechanism**: `create_gltpm_window()`
- **Logic**: This is the finalized TPMOS standard. It reads `.gltpm` layout files (XML-like) and dynamically generates buttons based on the Piece's PDL DNA.
- **Project Status**: Both `fuzz-op-gl` and `piececraft-3d` have modern layouts in their `layouts/` directories.

## 3. Why the Confusion?
- **Fuzz-Op-GL**: It exists in both worlds. When you launch it from "Desktop", you get the old hardcoded window. When you launch it from "GLTPM Apps", you get the modern layout.
- **Piececraft-3D**: It has already been "modernized" in both menus, so it looks consistent regardless of where you click it.

## 4. Proposed Resolution (Roadmap)

### Phase 1: Rename & Clarify
- Rename "Desktop Apps" to **"Project Explorer"**.
- Rename "GLTPM Apps" to **"Standalone Layouts"** or merge them into the Project Explorer.

### Phase 2: Consolidation
- Update the Desktop menu logic to point all projects (like `fuzz-op-gl` and `op-ed-gl`) to their respective `.gltpm` files, just like `piececraft-3d` does.
- This will make `create_mirrored_window()` obsolete.

### Phase 3: Cleanup
- Remove the hardcoded menu definitions from `gl_desktop.c`.
- Delete `create_mirrored_window()` to ensure there is only one "Source of Truth" for how a project renders in 3D.
