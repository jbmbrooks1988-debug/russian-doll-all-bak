# TPM-Compliant Tool Permission System Design
**Date:** 2026-05-26
**Status:** PROPOSAL / INVESTIGATION

## 1. The "Thin Theater" Approach
Following the Fuzz-Op pattern, the UI should be a hollow projection. The manager owns the permission state and only projects "Allow/Deny" buttons when it is specifically in the `AWAITING_PERMISSION` state.

### Key Components
- **Manager State:** A robust FSM transition from `THINKING` -> `AWAITING_PERMISSION`.
- **Dynamic Projection:** Use a variable `${tool_methods}` in `gem-dev.chtpm` that is exclusively managed by the `write_gui_state()` function.
- **Input Interception:** The `process_input_trigger()` function must act as a gatekeeper.

## 2. Robust Input Routing
The previous failure was primarily due to "y/n" leaking through to the AI.

### Interception Logic
```c
void process_input_trigger(void) {
    char *input = get_gui_var("input_text");
    if (!input) return;

    if (strcmp(g_ai_state, "AWAITING_PERMISSION") == 0) {
        // Intercept ALL text input during this state
        char *cmd = trim_str(input);
        if (strcasecmp(cmd, "y") == 0 || strcasecmp(cmd, "yes") == 0) {
            handle_permission_choice(true);
        } else if (strcasecmp(cmd, "n") == 0 || strcasecmp(cmd, "no") == 0) {
            handle_permission_choice(false);
        } else {
            snprintf(g_sys_msg, sizeof(g_sys_msg), "Invalid input. Please type [Y]es or [N]o.");
        }
        // Clear input box and trigger render WITHOUT calling start_ai_query
        clear_input_box();
        return;
    }
    
    // Normal operation
    start_ai_query(input);
}
```

## 3. Dynamic Button Projection
Instead of perpetual buttons, use indices 6 and 7 only when needed.

### Manager Projection
```c
if (strcmp(g_ai_state, "AWAITING_PERMISSION") == 0) {
    snprintf(g_tool_methods, sizeof(g_tool_methods), 
        "<button label=\"[6] Allow %s\" onClick=\"SET_ALLOW\" /><br/>"
        "<button label=\"[7] Deny %s\" onClick=\"SET_DENY\" />", 
        g_pending_tool, g_pending_tool);
} else {
    g_tool_methods[0] = '\0'; // Projected away
}
```

### Layout Integration
```xml
<text label="║  " /><cli_io id="input_text" label="Ask Agent: " /><text label="  ║" /><br/>
${tool_methods}
```

## 4. Handling Commands (SET_ALLOW / SET_DENY)
The manager's history loop must specifically look for these custom commands.

```c
if (strstr(line, "SET_ALLOW")) {
    handle_permission_choice(true);
} else if (strstr(line, "SET_DENY")) {
    handle_permission_choice(false);
}
```

## 5. Visual Attention (Bold/Color)
Since the CHTPM parser is plain ASCII, "attention" is achieved through:
1.  **Status Line Flashing:** Rapidly toggling a byte in `frame_changed.txt` to wake the renderer.
2.  **Box Borders:** Changing the header border from `═` to `*` or `!` when waiting.
3.  **Clear System Messages:** Using `[!] ALERT: ...` prefixes in `g_sys_msg`.
