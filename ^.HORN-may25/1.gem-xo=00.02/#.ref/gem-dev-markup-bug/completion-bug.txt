# Bug Investigation: '*' Completion Trigger

## Symptoms
* User types `*` in the `cli_io` field.
* `input_text` in `gui_state.txt` updates correctly (verified by frames).
* `Suggestions: ` area remains empty or shows no buttons.
* Manager seems to stay in `IDLE` or at least doesn't populate `g_completion_area`.

## Hypotheses

### 1. History File Missing Keystrokes
The `main` loop only triggers on changes to `pieces/apps/player_app/history.txt`. 
If the CHTPM parser's `cli_io` component handles character typing internally without writing each ASCII code to `history.txt`, the manager will never see the `*` key and thus never enter `COMPLETION_MODE`.

**Status**: Checking `history.txt` now.

### 2. Prefix Parsing Failure
In `update_completions`, we use `strrchr(input, '*')`. If the input has trailing spaces or the `*` is not where we expect, the prefix might be invalid.
However, `*` as the last character should yield an empty prefix, which `complete_path` handles as "list all in current dir".

### 3. `complete_path` Tool Issues
If `run_tool("projects/gem-dev/ops/+x/complete_path", ...)` fails or returns an error, `g_completion_area` might be empty.
We should check if the tool is compiled and executable in the manager's environment.

### 4. `state_changed` Not Triggering Render
If `update_completions` runs but `write_gui_state()` and `trigger_render()` aren't called correctly, the UI won't show the new markup.
The `main` loop has `state_changed = 1`, which should trigger `write_gui_state()`.

## Proposed Debugging Steps
1.  Verify `history.txt` contents after typing `*`.
2.  Add debug logging to `manager_debug.log` inside the `key == '*'` block.
3.  If `history.txt` doesn't log characters, refactor the manager to poll `input_text` for changes instead of relying solely on `history.txt`.

## New Bug Findings (2026-05-28)
### 1. Persistence Issue
`cli_buffers.txt` is an append-only log that persists across sessions. On startup, the manager reads the entire file and finds the last `i` line. If that line contains a `*` from a previous session, `COMPLETION_MODE` triggers immediately even if the current `input_text` is empty.
**Fix**: Manager should record the file size of `cli_buffers.txt` on startup and only process appends after that point.

### 2. Update Spamming
The manager currently runs the completion logic (including tool execution and markup generation) on every iteration of the `while(!g_shutdown)` loop (every 100ms) as long as `*` is present. This is extremely inefficient and causes UI flickering/spam.
**Fix**: Only run `update_completions` if the input string has actually changed since the last check.
