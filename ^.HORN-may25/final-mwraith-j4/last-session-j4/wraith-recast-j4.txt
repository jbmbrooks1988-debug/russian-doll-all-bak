1. IDENTIFICATION OF FALSE ASSUMPTIONS

Previous Agent Deviation:
I incorrectly assumed Wraith should be a "Virtual CHTMGL Parser" that processes a new markup standard before the host theater even sees it. This led to redundant `<panel>` tags, hardcoded geometry in layouts, and a fragile "flattening" bridge.

The Systemic Error:
I treated Wraith as a THEATER (Parser/OS) when it is actually a PROJECT (Map/Piece). By building a projector-style parser first, I bypassed the TPM foundation (CHTPM) and created a "ghost" architecture that does not comply with the `fuzz-op` standard of auditable, file-backed map composition.

2. THE CORRECTED INTENTION: WRAITH AS A SOVEREIGN MAP

In the True Piece Method, the Desktop is not a "UI"; it is a MAP.
- The Desktop Background: The terrain.
- The Windows: Dynamic map entities (pieces) with `pos_x`, `pos_y`, and `pos_z`. They are spawned, moved, and deleted by the manager; they are NOT static fixtures of the theater.
- The Mousehand: The player/xlector cursor on that map.

Wraith's standard of perfection is not "better rendering," but "better orchestration" of map pieces (windows) using the existing CHTPM foundation.

3. THE NEW ARCHITECTURAL SCAFFOLDING (The Fuzz-Op Model)

A. The Layout (Standard CHTPM):
`projects/wraith-pm/layouts/desktop.chtpm` will be a standard ASCII file.
It will contain one primary projected surface: `${game_map}`.

B. The Composer (The Desktop Renderer Op):
Instead of a complex parser, we will build a `wraith_render_desktop.c` Op.
1. It initializes a 96x54 character buffer (the desktop grid).
2. It draws the "Terrain" (Background, Desktop Banner, Taskbar).
3. It reads `windows_state.pdl` (The Pieces).
4. It iterates through active windows, sorted by Z-index.
5. For each window, it draws chrome (borders, title) and content (from `.view.txt`) into the buffer.
6. It writes the final buffer to `projects/wraith-pm/manager/view.txt`.

C. The Manager (The Orchestrator):
`wraith-pm_manager.c` will follow the `fuzz-op_manager.c` pattern:
1. Polls `history.txt` for input (Mouse/Keys).
2. Translates input into state mutations (e.g., `SET window_1 pos_x 20`).
3. Calls the Composer Op.
4. Pulses `pieces/display/frame_changed.txt` with marker 'W'.
