# MOUSE & NAV FIX REPORT (WRAITH PM)

## 1. ARCHITECTURAL COMPARISON & FINDINGS

### A. Mouse Capture (Wraith vs. Mouse-Test)
- **Status:** FAIL (Coordinates static at 80, 486).
- **Cause:** Coordinate Desync. 
  - `mouse-test_manager.c` uses `sscanf(p, "%d %d %d", &mouse_btn, &mouse_x, &mouse_y)` where `p` is `MOUSE_MOVE 35 58 17`.
  - **The Error:** My Wraith manager used `sscanf(cmd, "MOUSE_MOVE %d %d %d", &btn, &mx, &my)`. 
  - **The Impact:** It was swapping `btn` and `x` in some versions, but more importantly, `mx * 10` was being applied to a coordinate that might already be in pixels OR was being incorrectly interpreted as a cell.
  - **Static Coordinates:** The reason "80, 486" stayed static is that `mouse_x` and `mouse_y` in `state.txt` were being overwritten by the same calculated value every time because the `sscanf` was failing to pick up the *actual* changing values in the history stream.

### B. Navigation (Wraith vs. CHTPM/Fuzz-Op)
- **Status:** FAIL (`[>]` marker missing).
- **Cause:** Scope and Index Mismatch.
  - `chtpm_parser.c` uses `focus_index` and `navigable` flags.
  - Wraith tries to manually manage `selected_index` and `nav_scope`.
  - **The Error:** `sync_focus_from_mouse` was correctly identifying the terminal window but failing to properly update the `selected_index` based on the mouse position.
  - **The Logic Gap:** The `[>]` indicator logic in `write_terminal_view` depended on `selected_index` and `nav_scope` being in sync. If one drifts, the marker disappears.

### C. Architectural Misassumptions
- **Assumption:** Window lifecycle can be managed by simple string replacement in `windows_state.pdl`.
- **Reality:** String replacement is brittle. If a value changes length (e.g., `x=9` to `x=10`), it can corrupt the PDL record.
- **Intent Drift:** The "Game Map" was hardcoded as open. It must be spawned.

## 2. RECOVERY PLAN (PHASE J6)

### 1. Fix the "Sticky" Coordinates
- **Correct Order:** Use `sscanf(p, "MOUSE_MOVE %d %d %d", &btn, &mx, &my)`.
- **Pixel Authority:** Standardize on pixel coordinates (Cells * Scale) in all state files.

### 2. Move to "Full-Line" PDL Rewrite
- Replace the brittle `modify_window_pdl` with a `rewrite_window_state` function that uses structured data to ensure valid PDL output.

### 3. Restore Project-Driven Spawning
- Clear `windows_state.pdl` of everything except the Terminal.
- Ensure `apply_key_command` (Enter) triggers `spawn_window`.

### 4. Direct Debugging
- Add `fprintf(stderr, ...)` to the manager's command loop to log EXACTLY what it thinks the mouse coordinates are after `sscanf`.

---
**Verdict:** The system is "Loop-Locked" by stale data and brittle file writes. Phase J6 will break the lock.
