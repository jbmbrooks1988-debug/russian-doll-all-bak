# 🏗️ RPGAtlas: Prototype Refactor Roadmap (J14 Edition)

This document outlines the systematic refactor of RPGAtlas from modern object-literals/closures to the classic RPG Maker MV/MZ "Prototype" architecture.

---

## 🛠️ Phases of Implementation

### Phase 1: The Foundation (Core Extensions)
*   **Action**: Create `js/rpg_core.js` (or extend `js/data.js`).
*   **Goal**: Add common utility methods to standard JS types.
*   **Tasks**:
    *   [x] Implement `Number.prototype.clamp(min, max)`.
    *   [x] Implement `Number.prototype.mod(n)`.
    *   [x] Implement `String.prototype.format(...args)`.
    *   [x] Implement `Array.prototype.equals(array)`.
    *   [x] Implement `Array.prototype.clone()`.

### Phase 2: Data Objects (The Game_* Classes)
*   **Action**: Create `js/rpg_objects.js`.
*   **Goal**: Move logic from `js/engine.js` helper functions into formal constructor classes.
*   **Tasks**:
    *   [x] `Game_Actor`: Handle stats, exp, equipment, and learned skills.
    *   [x] `Game_Enemy`: Handle stats, actions, and rewards.
    *   [x] `Game_Map`: Handle tile access, passability, and event management.
    *   [x] `Game_Event`: Handle page state and movement logic.
    *   [x] `Game_Interpreter`: Port the `Interp` class to `Game_Interpreter.prototype`.

### Phase 3: System Managers (The *_Manager Statics)
*   **Action**: Create `js/rpg_managers.js`.
*   **Goal**: Decouple global state management from the main engine loop.
*   **Tasks**:
    *   [x] `DataManager`: Handle project loading, saving, and migration.
    *   [x] `SceneManager`: Handle switching between title, map, and battle.
    *   [x] `BattleManager`: Encapsulate the turn-based combat logic.
    *   [x] `PluginManager`: Formalize how plugins are loaded and hooks are registered.

### Phase 4: Engine Integration & Refactoring
*   **Action**: Modify `js/engine.js` and `js/editor.js`.
*   **Goal**: Replace all old logic calls with the new class-based system.
*   **Tasks**:
    *   [x] Update `newGame()` to instantiate `Game_Actor` objects.
    *   [x] Update `transferPlayer()` to use `Game_Map` methods.
    *   [x] Ensure `js/editor.js` DOM builder remains compatible with object properties.
    *   [x] **Naming**: Finalized descriptive all-caps globals `DATABASE` and `SESSION`.

### Phase 5: The "Monkey-Patch" Test Suite
*   **Action**: Create `tests/prototype.test.js`.
*   **Goal**: Verify that the engine is now fully moddable.
*   **Tasks**:
    *   [x] Test 1: Override `Game_Actor.prototype.param` via a dummy plugin.
    *   [x] Test 2: Hook into `Game_Interpreter.prototype.exec` to log custom commands.
    *   [x] Test 3: Verify `Game_Map` Z-sorting works (Visual Z prep).

---

## ✅ Refactor Status: COMPLETE

The RPGAtlas engine has been successfully refactored to a **Prototype-Based Architecture**. 
*   **Globals**: `window.DATABASE` and `window.SESSION` provide clear, descriptive access to game data and state.
*   **Extensibility**: All core classes (`Game_Actor`, `Game_Map`, etc.) are now fully moddable via standard prototype aliasing.
*   **Stability**: The core utility extensions (`.clamp()`, `.format()`, etc.) are in place and verified.

---

## 📈 Key Performance Indicators (KPIs)

1.  **Plugin Interoperability**: 100% of core methods must be "monkey-patchable" (aliasable and replaceable) without breaking the engine.
2.  **Sample Project Parity**: The *Atlas Quest* sample game must play identically to the pre-refactor version (no functional regressions).
3.  **Frame Rate Parity**: Drawing routines must maintain 60FPS at 1.0x scale, despite the overhead of prototype method lookups.
4.  **Boilerplate Consistency**: All new classes must follow the standard `this.initialize.apply(this, arguments)` pattern for familiarity.
5.  **Z-Level Readiness**: The `Game_Map` and `Game_Character` prototypes must include placeholder `z` properties for Phase 1 of the 3D Roadmap.
