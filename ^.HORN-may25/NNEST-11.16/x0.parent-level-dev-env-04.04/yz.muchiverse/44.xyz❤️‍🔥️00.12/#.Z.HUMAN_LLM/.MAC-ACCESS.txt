RULES
================================================================
R1. NEVER run trainer/forward/backward loops on this Linux box. The
    trainer spawns ~3000 system() calls + fscanf churn per run. Offload.
R2. Compile on the Mac (gcc on macOS is fine for these C files):
    for f in forward_prop backward_prop optimizer trainer vocab_model \
             chatbot_moe_v1 attention mlp_layer; do
      gcc "$f.c" -o "+x/$f.+x" -lm
    done
R3. OLLAMA (10.0.0.144:11434) is for LLM inference (gemma3:270m). It is
    NOT a shell; you cannot run training through it. Training = SSH + gcc.
R4. If 1234 stops working, ask the human for the new pass and update this
    file (this is the single source of truth for Mac access).
R5. Mind the Mac's resources too: don't run 10 parallel trainers. One at
    a time. It's the shared LAN LLM host.
R6. CLEANUP: if a local SSH session dies (Ctrl-C, disconnect, timeout), the
    remote trainer may keep running. Before/after any train run, check and
    kill leftovers so we never leave orphan procs on the Mac:
      ssh ... "pgrep -fl 'tomom-qroq' || echo clean"
      ssh ... "pkill -f tomom-qroq && echo killed"   (no matching procs = no-op, safe)
    Also clean remote temp dirs from debug sessions when done:
      ssh ... "rm -rf /tmp/ghd* /tmp/ghmini* /tmp/ghtrace* /tmp/ghopt* /tmp/gh_dbg*"
