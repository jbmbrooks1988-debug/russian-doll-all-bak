# Phase 2 Alignment Explainer

Your stated agenda:
- Refactor code out of `gl_desktop.c` into Ops to reduce LOC.
- Move toward a render pipeline that resembles the ASCII side of TPMOS.
- Improve auditability before phase 3.
- Delay HTML-like markup tag implementation until after the pipeline is cleaner and more auditable.

Does the previous phase 2 plan align?
- Partly, but it was too narrow.
- It aligned with preserving behavior and starting an Ops boundary.
- It did not clearly prioritize reducing `gl_desktop.c` LOC.
- It over-focused on `op-wm` as the first/main objective.
- It treated audit output as a small side task instead of a central render-pipeline goal.
- It did not clearly say that phase 3 markup work should wait until Ops and audit rendering are established.

Refactored phase 2 direction:
- Phase 2 should be "Ops extraction and auditable render pipeline", not "WM-first stabilization".
- The immediate target is to remove self-contained responsibilities from `gl_desktop.c` into independent Ops.
- The render path should gain an ASCII-style logical frame similar to the existing TPMOS ASCII-side approach.
- OpenGL should increasingly consume serialized logical state instead of owning all layout decisions directly.
- Tree-based positioning should stay explicit so phase 3 markup nodes can use hierarchical layout and clipping rather than ad hoc absolute coordinates.
- Window-manager fixes still matter, but only as constraints that must not regress while extracting code.

How this supports phase 3:
- HTML-like markup tags will be safer once layout/rendering has an auditable intermediate form.
- The future tag renderer can target the logical frame/scene representation first.
- Physical OpenGL drawing can then be treated as a consumer of audited layout state.
- This reduces the chance of black-box artifacts and coordinate regressions when new tags are added.
- The tree/scene-graph step is not optional if markup nodes are supposed to be structured and auditable.

Practical phase 2 success criteria:
- `gl_desktop.c` loses meaningful LOC by moving discrete behavior into Ops or standalone modules.
- At least one extracted Op runs independently and communicates through files/markers.
- A persistent logical frame/audit file exists and can be inspected without a GL session.
- Current behavior stays stable: tab restore, minimize, active window, project selection, terminal, and ASCII mirror behavior.
- No broad project discovery/default-size changes happen unless explicitly requested.
