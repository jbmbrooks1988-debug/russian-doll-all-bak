# Phase 2 Plan

Theme:
- Ops extraction and auditable render pipeline.

Purpose:
- Reduce `gl_desktop.c` LOC by moving self-contained responsibilities into TPMOS-style Ops.
- Align GL-OS rendering with the ASCII side of TPMOS by adding a file-backed logical/audit frame.
- Prepare for phase 3 HTML-like markup tags by making layout/render state inspectable before OpenGL draws it.
- Preserve the tree-based positioning strategy so markup nodes can later be rendered hierarchically instead of with fragile absolute placement.

Non-goals:
- Do not implement new HTML-like markup tags yet.
- Do not make broad project discovery or default-size changes.
- Do not rewrite the whole renderer in one pass.
- Do not break the fixed toolbar tab restore behavior.

Phase 2 work order:
1. Identify extractable responsibilities in `gl_desktop.c`
- Prefer code that already reads/writes files or has clear input/output boundaries.
- Good early candidates: project discovery, metadata loading, terminal/session state, menu/context data, and audit-frame generation.
- Keep window behavior stable while extraction happens.

2. Define the logical frame contract
- Create a persistent audit file that describes what should be drawn.
- Use an ASCII-side style format: frame header, scene/window ids, bounds, hierarchy, labels, and metadata references.
- The audit frame should be readable with `cat` and useful without launching GL.

3. Extract the first low-risk Op
- Start with an Op that reduces LOC without owning fragile GL behavior.
- Good candidate: project discovery or metadata extraction.
- Communicate by state files and marker files, not in-memory globals.

4. Connect GL-OS to the extracted state
- Keep `gl_desktop.c` functional during transition.
- Read the extracted Op output where practical.
- Keep a fallback path until behavior is verified.

5. Move render decisions toward the audit frame
- Add logical frame emission before or alongside current OpenGL drawing.
- Do not immediately replace all physical drawing.
- Use the audit frame to compare expected layout against what GL should render.
- Keep the node tree as the source of relative positioning and clipping semantics.

6. Verify after each narrow change
- Compile after every small extraction.
- Manually verify tab restore, minimize, active window selection, project selection, terminal behavior, and ASCII mirror behavior.
- Only proceed to phase 3 markup work after phase 2 has a stable auditable pipeline.

Phase 2 success criteria:
- `gl_desktop.c` is smaller because at least one real responsibility moved out.
- At least one native-style Op runs independently and uses file/marker communication.
- A logical/audit frame exists and records meaningful render/layout state.
- Tree-based positioning is defined clearly enough that phase 3 markup nodes can be rendered hierarchically.
- Current GL-OS behavior remains stable.
- Phase 3 markup tags have a cleaner target than direct ad hoc OpenGL coordinate code.

Concrete GlOS cleanup order:
1. Split the host into "orchestrate vs execute" responsibilities.
- Keep `gl_desktop.c` as the event loop, window bridge, and fallback renderer only.
- Move file-backed state loading, project/session discovery, and window metadata assembly into standalone Ops.
- Keep existing behavior paths intact until each extracted Op can replace the in-file version directly.

2. Define the audit frame as the contract.
- Write one persistent logical frame file per render pulse.
- Include frame id, active layout, focused window, window bounds, z-order, layout tree nodes, and action targets.
- Keep the format plain ASCII so it can be inspected with `cat` and diffed without GL.

3. Extract low-risk Ops first.
- Start with project/session discovery, marker handling, and metadata normalization.
- Then extract render-input prep, window list assembly, and audit-frame emission.
- Leave fragile focus, minimize, tab restore, and active-window selection logic in place until the file-backed replacement proves stable.

4. Move layout decisions toward the audit frame.
- Serialize tree-position data before drawing.
- Preserve hierarchical positioning data so markup can later consume nodes relative to parents instead of using absolute ad hoc math.
- Treat OpenGL output as a consumer of the audited logical frame, not the source of truth.

5. Gate phase 3 behind phase 2 stability.
- Do not add markup tags until the audit frame is stable and at least one Op is independently testable.
- Once the pipeline is auditable, phase 3 can consume the same tree data for markup layout and clipping.

Practical acceptance checklist:
- `gl_desktop.c` loses meaningful LOC.
- At least one Op can run from the CLI and produce a file-backed result.
- The logical frame is readable and useful without a GL session.
- Current desktop behavior still works: toolbar restore, minimize, active-window selection, terminal interaction, and project selection.
- The cleanup path makes markup/layout work a downstream step instead of a rewrite.
