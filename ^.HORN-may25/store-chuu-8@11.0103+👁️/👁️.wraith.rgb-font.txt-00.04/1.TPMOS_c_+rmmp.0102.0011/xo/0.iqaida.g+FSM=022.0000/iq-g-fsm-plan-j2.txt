IQ-G-FSM Plan J2

Target bot:
  1.TPMOS_c_+rmmp.0102.0010/xo/0.iqaida.g+FSM=022.0000

Current shape observed in code:
- `agent.c` is an interactive CLI agent.
- It reads typed user input from stdin.
- It resolves model/API settings from `config/` and `state/`.
- It calls helper tools such as `tools/json_state`, `tools/json_parser`,
  `tools/gemini_payload_builder`, `tools/list_dir`, `tools/search_in_files`,
  `tools/edit_file`, `tools/web_search`, and `tools/cmd_exec`.
- The current control loop is user-first, terminal-first, and Gemini-backed.

Goal for the next stage:
- Add file-driven input as a first-class source alongside typed CLI input.
- Let FSM and RL choose which input to feed the bot.
- Keep the Gemini-backed CLI as one execution backend, not the only intake path.
- Prepare this bot for supervised training and knowledge distillation later.
- Keep the long-term direction small and controllable: FSM + RL + curriculum + memory,
  with the LLM as one node in the machine, not the machine itself.

Planned input sources:
- Direct user stdin.
- External text files dropped into a watched directory.
- Replay files from prior sessions.
- Curriculum files selected by FSM policy.
- RL-selected examples for reward and punishment runs.

Planned control layers:
- FSM layer for state transitions and mode selection.
- RL layer for reward, punishment, and selection pressure.
- Input router layer for deciding which file or stream becomes the next prompt.
- Training recorder layer for saving supervised examples, labels, and outcomes.

Planned future file roles:
- `state/input_queue/` for pending file-backed prompts.
- `state/selection/` for FSM and RL decisions.
- `state/training/` for supervised examples and distillation traces.
- `config/` for mode settings and curriculum knobs.
- `debug/` for audit logs and frame-by-frame inspection.

Non-goals for the first pass:
- Do not replace the current CLI loop all at once.
- Do not build a large general-purpose training system yet.
- Do not make the model selector depend on hidden state that cannot be audited.

Suggested implementation order:
1. Add a file-backed prompt reader.
2. Add a small FSM that can choose between stdin, file input, and replay.
3. Add RL reward/punish hooks around input selection outcomes.
4. Add logging for chosen inputs, chosen mode, and result quality.
5. Add supervised export files for later distillation.
6. Only after that, expand the curriculum and policy logic.

Implementation note:
- This bot should become able to operate from textfile inputs first, then learn to
  choose inputs through FSM/RL, then later support supervised training and distillation.
- That is the intended path for iqamoji-xo5 and related iqa bots.
