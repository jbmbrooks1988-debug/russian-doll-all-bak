## Mission

Wraith is the TPMOS auditable GL desktop effort.

The goal is not to make GL mirror ASCII glyphs forever. The goal is:

- one Wraith session truth
- one semantic scene/object stream
- one ASCII audit projection for humans and agents
- one graphical RGB/GL projection for actual UI presentation
- receipts that prove what each stage consumed, converted, uploaded, and displayed

ASCII is the audit/debug lens. GL is the richer presentation lens. Both must remain close enough that mismatches are obvious and actionable.

## Current Architecture Contract

Core rule:
- one scene, two presenters
- file-owned project truth

Important terms:
- `${game_map}` is the current canvas-like payload name, matching `fuzz-op` / `fuzz-op-gl`.
- `INTERACT` is the direct-control action for a map/surface.
- `is_map_control` is the modal state flag.
- Do not rename these to `canvas` yet. Docs may describe them as canvas-like, but implementation should stay uniform for now.
- Do not hardcode project-specific bodies, scene records, ops, cube/map/widget/emoji logic into `wraith-alpha_manager.c`.
- Wraith Alpha discovers and hosts internal projects; each project owns its own layouts/state/body/scene/assets.
- If it is not in a file or receipt, it is not project truth.

## What Was Fixed

The recent parity/debug sprint fixed the main Wraith GL basics:

- GL is again a thin RGB texture presenter, not a second UI owner.
- `wraith_rgb_daemon` owns conversion from ASCII or semantic objects into RGBA.
- `ASCII` / `GL` mode is controlled by Wraith session state.
- stale `wraith-pm` semantic artifacts are rejected.
- GL startup no longer displays stale previous-session frames.
- GL can navigate 10+ indices by accumulating digits like ASCII.
- GL mouse coordinates are mapped through the displayed texture viewport, including fullscreen letterbox/scale cases.
- `current_frame.receipt.pdl` now includes timestamps, source mtimes, object bounds, render bounds, text bounds, hit bounds, focus bounds, glyph size, cell size, z, label, action, and containment data.
- `gl_display.receipt.pdl` now records the RGBA checksum/byte count that GL uploaded plus viewport and display scale.
- `gl_input.receipt.pdl` records raw mouse coordinates, texture viewport, mapped texture coordinates, and inside/outside status.
- the major footer-text drift bug was fixed: semantic text was drawing at `GLYPH_H=16` row spacing while panels/receipts used `cell_height_px=18`.

Verification rule:
- `current_frame.receipt.pdl:render_checksum_fnv1a64` should match `gl_display.receipt.pdl:loaded_rgba_checksum_fnv1a64`.
- If those differ, GL is not displaying the frame the RGB daemon says it rendered.
- If those match but the screen looks wrong, inspect `text_px_*`, `hit_px_*`, and `focus_px_*` for the object in question.

Current generic `INTERACT` bridge:
- A project-owned `session/scene.objects.pdl` surface may declare `nav=<n>` and `action=INTERACT`.
- When external nav selects that surface, the selector is `[>]`.
- Pressing Enter on that nav enters project map/interact mode and writes `is_map_control=1` in the active project's `session/state.txt`.
- While map/interact mode is active, the same selected surface should display `[^]` to show keyboard ownership moved from Wraith shell nav to the project `${game_map}` surface.
- `ESC` exits map/interact mode and writes `is_map_control=0`.
- While active, normal keypresses are appended to the active project's `session/history.txt`; they should not be interpreted as Wraith shell nav.
- This bridge is generic host behavior. The project-specific manager/ops should consume `session/history.txt` and update project-owned `state.txt`, `wraith_body.txt`, and `scene.objects.pdl` frame by frame.
- `session/history.txt` has been seeded in `wraith-3d-cube`, `piececraft-wraith`, `chtmgl-wraith`, and `emoji-studio-wraith` so input history is auditable before the first event.

## How To Work Safely

Before changing coordinates or styling:
- inspect `current_frame.receipt.pdl`
- inspect `gl_display.receipt.pdl`
- compare checksums
- inspect `text_px_*`, `hit_px_*`, and `focus_px_*`

Before adding a new Wraith project:
- confirm it belongs under `projects/wraith/wraith-projects/`
- confirm it appears in the Wraith internal launcher
- confirm launching it mutates Wraith's window registry, not the top-level TPMOS loader

Before adding richer GL behavior:
- keep `wraith_gl.c` thin
- put conversion logic in `wraith_rgb_daemon.c`
- put session/window truth in the manager/session artifacts
- keep receipts strong enough that a future agent can debug from files alone
