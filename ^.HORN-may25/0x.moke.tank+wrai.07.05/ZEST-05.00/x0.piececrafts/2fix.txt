2FIX: PIECECRAFT-WRAITH 3D TOGGLE — WHY IT LOOKS ALMOST IDENTICAL TO 2D
================================================================================
Date: July 2, 2026 (evening)
Status: INVESTIGATED, remedy scoped, NOT implemented (real feature, not a bug fix)

(Note: this file previously contained an earlier bug report — "manager
daemon not launching" — from earlier in the day. That issue is fully
resolved; see x0.piececrafts/HANDOFF-WRAITH-STATE-MYSTERY.md for the full
history of that fix and everything since. This file now covers a new,
unrelated investigation: the 3D toggle.)

--------------------------------------------------------------------------------
WHAT YOU SAW
--------------------------------------------------------------------------------

2D mode: flat top-down grid, obstacles subtly shaded/lifted, xelector marked
with a yellow crosshair.

3D mode (after tonight's fix): same flat top-down grid. The only change is
every grass tile now has a ~1-2 pixel "lift" edge — visually almost
imperceptible. NOT what was expected.

Reference (gl-os piececraft-3D, a different project entirely): a genuine
perspective camera view — tiles shrink and recede toward a horizon/vanishing
point, like looking across a field at an angle. Real 3D.

--------------------------------------------------------------------------------
ROOT CAUSE
--------------------------------------------------------------------------------

These are two fundamentally different rendering techniques, and Wraith's
renderer only has the simpler one.

**What I built tonight (`draw_tile_zmap_preview()` in
`projects/wraith-alpha/plugins/wraith_rgb_daemon.c`):**
A flat top-down grid where each tile is drawn as an axis-aligned rectangle
(`fill_rect_px`). "3D" was faked by giving each tile a colored "side" strip
below it (a `lift` in pixels) to suggest height — like a slightly raised
sticker, not a real camera looking at a scene from an angle. The 3D-mode
change I added tonight just gave grass tiles a small lift too (previously
only trees/rocks/walls had any lift at all). That's why it barely looks
different: it's a small tweak to an already-flat technique, not a new
technique.

**What the reference screenshot is doing (gl-os / PIECECRAFT-3D):**
Window title is "GL-OS Desktop", a completely separate subsystem from
Wraith's "Wraith Alpha RGB Mirror". The visible grid tiles are TRUE
perspective-projected quads: each tile's four corners are transformed
through a camera (position + pitch/yaw/roll + focal-length perspective
divide) before being drawn, so:
  - tiles further from the camera appear smaller
  - rows converge toward a horizon
  - a proper depth cue exists (this is real 3D projection math, not a
    lift/shading trick)

Confirmed this is a different code path — searched `pieces/display/gl_renderer.c`
and `pieces/chtpm/renderers/gl_renderer.c` for tile_zmap/grid-perspective
logic and found nothing. The pitfalls doc has several GL-OS-specific entries
(items #37-40: GL-OS input focus lock, idle throttle, joystick axis, GLUT
special-key registration) confirming GL-OS is its own GLUT/OpenGL-based
desktop shell, architecturally separate from Wraith's software RGBA
pixel-buffer renderer (`wraith_rgb_daemon.c`).

--------------------------------------------------------------------------------
THE GOOD NEWS: THE MATH ALREADY EXISTS, JUST NOT FOR GRIDS
--------------------------------------------------------------------------------

`wraith_rgb_daemon.c` is NOT starting from zero. It already has real 3D
rotation + perspective-divide math — in `draw_zslice_piece_preview()`
(used by wraith-3d-cube), which:
  1. Takes 8 cube vertices in local space
  2. Rotates them by (rx+pitch, ry+yaw, rz+roll) using standard 3-axis
     rotation matrices
  3. Applies a perspective divide: `perspective = focal / (focal + z2r + cam_z + 3.0)`
  4. Projects to 2D screen points and draws the 12 edges as a wireframe cube

This is the SAME category of math a perspective tile grid needs — it's just
currently wired to transform 8 vertices of ONE cube, not the 4 corners of
EVERY tile in a map.

--------------------------------------------------------------------------------
THE REAL REMEDY (scoped, not done — this is a real feature, not a bugfix)
--------------------------------------------------------------------------------

To make piececraft-wraith's 3D mode look like the reference image, someone
needs to write a genuine perspective grid renderer, reusing
`draw_zslice_piece_preview()`'s rotation/perspective math but applied
per-tile-corner across the whole map instead of per-vertex for one cube:

1. For each tile (row, col) in the map, compute its 4 corner points in
   world space (e.g. corner = (col*tile_size, 0, row*tile_size) for a flat
   ground plane, using row/col as X/Z and a fixed Y=0 or Y=height for
   walls/trees).
2. Run each corner through the same rotate+perspective-divide transform
   `draw_zslice_piece_preview()` already uses (rx/ry/rz or pitch/yaw/roll
   from a camera, focal length divide).
3. Instead of `fill_rect_px()` (axis-aligned rectangle), need a
   **quad-fill** function that can paint an arbitrary (non-axis-aligned)
   4-point polygon — `wraith_rgb_daemon.c` doesn't have one currently, only
   `fill_rect_px`, `draw_border_px`, `draw_line_px`. This is the biggest
   net-new piece of work: a scanline or triangle-based polygon fill routine.
4. Camera needs sensible defaults for a top-down-ish but angled view (e.g.
   pitch ~30-45 degrees looking down at the grid, positioned above and
   behind row 0) so the whole map is visible and recedes correctly —
   this needs tuning, not just plugging in arbitrary numbers.
5. Depth sorting: rows/tiles closer to the camera must be drawn AFTER
   (on top of) rows further away, or back tiles will incorrectly overlap
   front tiles. The current flat renderer never had to worry about this
   since nothing overlapped.

This is a genuine rendering-engine feature (polygon rasterization + camera
projection for a full grid), not a config toggle or small patch. Comparable
in scope to what already exists for wraith-3d-cube's single cube, but
extended to N tiles with proper depth ordering and quad fill instead of
wireframe edges.
