   TWO separate things both claim to show this text and neither is
   confirmed working:
   a) The OLD line in layouts/piececraft-wraith.chtpm
      (`<text label="Position: (${xel_x}...)"/>`) — this is DEFINITELY
      dead code, confirmed earlier tonight: Wraith never parses a
      is_map_control project's own .chtpm file content at all.
   b) The NEW coords_hud object we added to scene.objects.pdl
      (`OBJECT tag=text id=coords_hud ... y=20 ... label=Position: (...)`)
      — this SHOULD render (tag=text objects don't get the early-return
      that tile_zmap gets), but it's positioned at y=20/21, directly below
      the map which occupies y=6 through y=19. Leading theory: the
      window's actual rendered height may not extend that far down, so
      the text is being clipped off-screen rather than failing to
      generate. NOT CONFIRMED — needs checking against the window's real
      h= value and how Wraith clips content below a window's declared
      height.

   Next step for tomorrow: check session/current_frame.objects.pdl (or
   wherever wraith-alpha composes the final frame) after opening
   piececraft-wraith, and search for "coords_hud" to see if it's present
   in the composed frame at all. If it's present but off-screen, it's a
   clipping/positioning fix (move the HUD text into the map's own y-range
   instead of below it, or shrink the map height by 2 rows to make room).
   If it's ABSENT from the composed frame entirely, that's a different,
   deeper bug in how is_map_control windows assemble their body — the
   generic object-forwarding path we relied on (append_project_scene_objects)
   may not actually get invoked for is_map_control windows the same way
   it does for plain non-map windows. That would need tracing the same way
   we traced the tile_zmap rendering gap tonight.

2. 2D/3D MODE TOGGLE DOESN'T CHANGE THE GL VIEW
   Pressing 8 updates display_mode in state.txt (2d_topdown <-> 3d_voxel)
   correctly — this part works. But the GL tile grid itself never changes
   appearance between the two modes.

   THIS IS EXPECTED, not a new bug — documented earlier tonight and
   confirmed again by reading the code: draw_tile_zmap_preview() in
   wraith_rgb_daemon.c only has ONE rendering path (flat 2D tiles with a
   height/shading "lift" for trees/rocks/walls). There is no 3D/isometric
   rendering code at all, and nothing in that function reads
   display_mode. Toggling the mode changes the label text (if the HUD
   were visible) but was never wired to actually change what gets drawn.

   Fixing this for real means writing an actual second rendering path in
   draw_tile_zmap_preview() (or a new draw_tile_zmap_3d() function) that
   projects the same tile data with a 3D/isometric look when
   display_mode=3d_voxel, and branching on that field (which would need
   to be threaded through from scene.objects.pdl's MAP_SOURCE label,
   similar to how selected=X,Y is threaded through now for the marker).
   This is real net-new engine work, not a quick fix — plan for it as its
   own task, not a continuation of tonight's bug-fixing.
