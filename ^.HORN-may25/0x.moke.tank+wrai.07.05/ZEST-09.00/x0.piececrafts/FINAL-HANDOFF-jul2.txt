HOW TO PLAY
================================================================================

1. Open Wraith
2. Select "PIECECRAFT WRAITH" project
3. Wait 2 seconds for manager to launch
4. You'll see:
   - Map with xelector (>) at center
   - Coordinates display: Position: (x, y, z)
   - Current mode: 2D or 3D
   - Debug status: ON or OFF
   - Control overlay with all hotkeys

5. Controls:
   - ↑ (Arrow Up) or 1002      = Move up (xel_y - 1)
   - ↓ (Arrow Down) or 1003    = Move down (xel_y + 1)
   - ← (Arrow Left) or 1000    = Move left (xel_x - 1)
   - → (Arrow Right) or 1001   = Move right (xel_x + 1)
   - X                         = Ascend (xel_z + 1, max 2)
   - Z                         = Descend (xel_z - 1, min 0)
   - 8                         = Toggle mode (2D ↔ 3D)
   - D                         = Toggle debug
   - ESC                       = Menu (Wraith)

TPMOS Pattern: Manager → State → Display

  New Functions:

    - ensure_project_manager() : Prevents duplicate launches via lockfile
  Triggered: When user selects a project in Wraith menu
  Status: ✅ Working perfectly

Component 2: piececraft-wraith_manager (Game Logic)
  Location: projects/wraith-alpha/wraith-projects/piececraft-wraith/manager/
  Role: Game state, input processing, map rendering
  Responsibilities:
    - Monitors history.txt for input events

================================================================================
DATA FLOW (Per Frame/Input)
================================================================================

1. INPUT PHASE:
   User presses key → Wraith captures → appends to history.txt

2. POLLING PHASE:
   piececraft-wraith_manager wakes (16ms interval, stat-based)
   Reads new entries from history.txt

3. PROCESSING PHASE:
   route_input() determines action
   Updates state: xel_x, xel_y, xel_z, display_mode, or debug_mode_on

4. RENDER PHASE:
   render_map_wraith op generates ASCII map
   Manager wraps in UI (title, status line, controls)
   Writes to wraith_body.txt

5. DISPLAY PHASE:
   Wraith reads wraith_body.txt
   Renders in window
   User sees updated map

Latency: ~50-100ms (input capture → display update)

================================================================================
STATE MACHINE
================================================================================

Input: key code
Processing:
  if key == 1000 (LEFT):
    if xel_x > 1: xel_x--
    render_map()
    save_state()
    trigger_render()

  if key == 1001 (RIGHT):
    if xel_x < 18: xel_x++
    render_map()
    save_state()
    trigger_render()

  if key == 1002 (UP):
    if xel_y > 1: xel_y--
    render_map()
    save_state()
    trigger_render()

  if key == 1003 (DOWN):
    if xel_y < 8: xel_y++
    render_map()
    save_state()
    trigger_render()

  if key == 'X' or 'x':
    if xel_z < 2: xel_z++
    render_map()
    save_state()
    trigger_render()

  if key == 'Z' or 'z':
    if xel_z > 0: xel_z--
    render_map()
    save_state()
    trigger_render()

  if key == '8':
    display_mode = (display_mode == 0) ? 1 : 0
    save_state()
    trigger_render()

  if key == 'D' or 'd':
    debug_mode_on = (debug_mode_on == 0) ? 1 : 0
    save_state()
    trigger_render()

Boundary Constraints:
  xel_x: [1, 18] (20-wide map, borders at 0 and 19)
  xel_y: [1, 8]  (10-tall map, borders at 0 and 9)
  xel_z: [0, 2]  (3 levels)

KNOWN LIMITATIONS
================================================================================

1. GL VISUALIZATION ISSUES (Not fixable at manager level)
   - GL renderer doesn't show xelector marker visually
   - GL renderer doesn't update when mode toggled
   - These are Wraith display-layer limitations
   - ASCII interface works perfectly (use that for game)

2. NO 3D VOXEL RENDERING
   - display_mode=3d_voxel sets state but no 3D rendering
   - Would require GL voxel engine (not implemented)
   - ASCII map is functional for gameplay

3. MAP SIZE FIXED
   - Only 20×10 maps supported
   - 3 Z-levels hardcoded
   - Extension would require render op modifications

4. SINGLE MAP INSTANCE
   - Only one active map (map_01)
   - No level switching or map management

5. NO COLLISION DETECTION
   - Can't move through trees (T) or rocks (R)
   - Movement is free-form (respects boundaries only)
   - Could be added to route_input() logic

TROUBLESHOOTING
================================================================================

Problem: "Missing project body file"
  Cause: Manager not running or crashed
  Fix: Check session/debug_log.txt for errors
       Restart Wraith and re-select project
       Verify manager binary exists at manager/+x/piececraft-wraith_manager.+x

Problem: No input response
  Cause: Manager not polling history.txt
  Fix: Check if debug_log.txt has "Key received" entries
       If not: manager crashed, check debug_log for error
       If yes: route_input() has issue, check if state.txt updates

Problem: Xelector goes off-screen
  Cause: Boundary check failed or render op issue
  Fix: Check state.txt values (xel_x should be 1-18)
       Check render_map_wraith.+x directly:
       ./ops/+x/render_map_wraith.+x 20 5 0 "/path/to/map_01_z0.txt"
       (Should not show > at position 20 because it's out of bounds)

Problem: Mode toggle doesn't work
  Cause: Key not reaching route_input() or render not triggering
  Fix: Check debug_log.txt for "TOGGLE_MODE" entry
       Verify state.txt display_mode changes
       GL visualization has known limitation (won't change)

Problem: Maps not changing on Z-level change
  Cause: render_map_wraith.+x not finding correct map file
  Fix: Verify maps exist: maps/map_01_z0.txt, z1.txt, z2.txt

PATTERN: WRAITH-HOSTED INTERACTIVE PROJECT
================================================================================

Use this as template for creating new interactive projects in Wraith:

1. Create project structure:
   projects/wraith-alpha/wraith-projects/[PROJECT]/
   ├── project.pdl (declare manager path)
   ├── manager/[PROJECT]_manager.c (game logic)
   ├── ops/src/[OP].c (rendering ops)
   ├── layouts/[PROJECT].chtpm (window structure)
   ├── maps/ (game data)
   └── session/ (runtime state)

2. In project.pdl, add:
   META | manager | projects/wraith-alpha/wraith-projects/[PROJECT]/manager/+x/[PROJECT]_manager.+x

3. In layout, hardcode module path:
   <module>projects/wraith-alpha/wraith-projects/[PROJECT]/manager/+x/[PROJECT]_manager.+x</module>

4. Manager must:
   - Poll session/history.txt for input
   - Update game state
   - Write session/wraith_body.txt with display content
   - Call trigger_render() on state change

5. Test with wraith-man-test as reference

This pattern is:
  ✓ TPMOS-compliant (state files, managers, ops)
  ✓ Wraith-compatible (uses wraith_body.txt)
  ✓ Scalable (works for any interactive game)
  ✓ Clean (modular, auditable)
