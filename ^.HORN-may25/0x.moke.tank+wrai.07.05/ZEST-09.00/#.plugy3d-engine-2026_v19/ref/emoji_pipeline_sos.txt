# Emoji Entity Pipeline Overview

This document explains the process of how emojis are sourced, processed, and rendered as 3D entities in the engine.

## 1. Source Emoji Data

The pipeline starts with a standard emoji data file from the Unicode consortium. The file `ref/!.emoji.xtract.stb]c4/emoji-test_14.0=BEST.txt` contains a list of all emojis with their codepoints, status (fully-qualified, component, etc.), and names.

## 2. Parsing the Emoji List

The Python script `ref/parse_emojis.py` is used to process the raw emoji data file.

- It reads `ref/!.emoji.xtract.stb]c4/emoji-test_14.0=BEST.txt`.
- It filters this list, by default only keeping emojis that are "fully-qualified" or "component". (Originally, it only kept "fully-qualified", which excluded many animal emojis like "cow" and "sheep". This has been modified).
- It writes the filtered list to `ref/parsed_emojis.txt` in a simple `codepoint|emoji|name` format.

This is a pre-processing step that should be run whenever you need to update the list of available emojis. (e.g., `python3 ref/parse_emojis.py`)

## 3. Generating Large Emoji Atlas (RESTORED APPROACH)

The original C program `ref/!.emoji.xtract.stb]c4/!.emoji-simplifier]png]d3.c` is responsible for creating a comprehensive texture atlas from ALL emojis.

- It reads `ref/parsed_emojis.txt` to identify all available emojis.
- It uses a system font (e.g., NotoColorEmoji.ttf) to render ALL emojis into a single large atlas.
- It creates a comprehensive PNG file named `ref/emoji_atlas.png` containing all emojis in a single row layout.
- The program also generates `ref/emoji_positions_map.txt` which maps emoji names to their positions in the atlas.
- This approach ensures real color emoji data is captured directly from the font rendering.

## 4. Extracting Emojis to CSV at Runtime (CORRECTED APPROACH)

When the application starts, the `EmojiEntityManagerPlugin` takes over with the updated pipeline:

- The plugin's `initialize` method first identifies which emojis are needed for the current session (defined in `session_emojis`).
- It calls the main C executable `ref/extract_emoji` to process the large atlas.
- The executable loads the full emoji atlas and the parsed emoji list, then finds the requested emoji by name and index.
- **Optimization:** The plugin first checks if the target emoji's CSV file (e.g., `data/entities/emoji/cow/cow.csv`) already exists. If it does, no processing is done, saving time.
- If the CSV doesn't exist, the executable extracts the specific emoji from the large atlas at its indexed position, downsamples it to an 8x8 grid, and saves it as a CSV file in the `data/entities/emoji/<emoji_name>/<emoji_name>.csv` format.
- The generated files are initially created in the current working directory, then automatically moved to the correct destination by the plugin code.

## 5. Loading and Rendering the 3D Model

- The `EmojiEntityManagerPlugin` then reads the newly created (or existing) CSV file.
- For each non-black pixel in the 8x8 grid, it generates a column of 8 voxels, effectively "extruding" the 2D image into a 3D shape.
- This 3D voxel model is then added to the main grid and rendered in the scene, appearing as a 3D entity.

## Legacy Files Status

- The old C file `ref/!.emoji.xtract.stb]c4/!.emoji-simplifier]png]d3.c` has been updated to also generate `emoji_positions_map.txt` for proper extraction.
- The large atlas `ref/emoji_atlas.png` is now actively used as the primary emoji source for real color data.
- The custom atlas approach was abandoned in favor of the original proven method that delivers real color emoji data.
