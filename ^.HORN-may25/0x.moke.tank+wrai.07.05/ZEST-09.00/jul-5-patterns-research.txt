Location: terminal/ops/src/wraith_project_input.c (exemplar)
Also used by: wraith-ed, every wraith project

  fprintf(f, "key2=%d\n", value2);

  rename(tmp_path, actual_path);

PATTERN 2: READING PROJECT.PDL (window geometry example)
========================================================
Location: wraith-alpha_manager.c & window-geom_manager.c

Format: SECTION | KEY | VALUE (pipe-delimited)
Example:
  WINDOW | window_x | 10
  WINDOW | window_y | 20
  WINDOW | window_width | 80
  WINDOW | window_height | 30

Read function pattern (from window-geom_manager.c:read_pdl_value):
  void read_pdl_value(const char *path, const char *key, char *dst, size_t dst_sz) {
      FILE *f;
      char line[MAX_LINE];

      dst[0] = '\0';
      f = fopen(path, "r");
      if (!f) return;

      while (fgets(line, sizeof(line), f)) {
          char *pipe1, *pipe2, *val, *nl;
          if (!strstr(line, key)) continue;
          pipe1 = strchr(line, '|');
          if (!pipe1) continue;
          pipe2 = strchr(pipe1 + 1, '|');
          if (!pipe2) continue;
          val = trim_str(pipe2 + 1);
          nl = strchr(val, '\n');
          if (nl) *nl = '\0';
          strncpy(dst, val, dst_sz - 1);
          dst[dst_sz - 1] = '\0';
          break;
      }
      fclose(f);
  }

Current status in wraith-alpha_manager.c:
  - READS window geometry from project.pdl (load_window_geometry_from_pdl exists)
  - Does NOT yet write window geometry back to project.pdl
  - This is where goal 4 (editable geometry) lives

PATTERN 4: CLI_IO & USER INPUT (GOAL 4)
=======================================
Location: terminal/layouts/terminal.chtpm

Markup pattern:
  <interact src="projects/wraith-alpha/wraith-projects/terminal/session/history.txt" />
  <button label="Start Typing" onClick="INTERACT" />

How it works:
  1. <interact src="..."> — defines which file to append input to
  2. onClick="INTERACT" — on button click, switches input mode
  3. User types into that file (char-by-char)
  4. wraith_project_input.c reads that file on every keystroke
  5. Parses KEY_PRESSED: <keycode> or COMMAND: <line>

For window-geom editable fields, we need:
  - NOT cli_io input (that's for shell-like input)
  - Instead: render editable text fields in layout
  - Capture SUBMIT clicks
  - Parse the input, validate, write to project.pdl

Pattern from terminal input example (wraith_project_input.c):
  - Read KEY_PRESSED lines from history
  - Accumulate into input_line buffer
  - On Enter (key 13), process the command
  - Same pattern can apply: numeric input → parse → validate → save

PATTERN 5: OUTPUT VIA SESSION/WRAITH_BODY.TXT
==============================================
Location: every wraith project's manager

Convention:
  - Session/wraith_body.txt is the generic body-render fallback
  - Every hosted project gets it for free
  - Manager writes plain text or markup to this file
  - wraith-alpha renders it unchanged

Current window-geom output pattern:
  - window-geom_manager.c writes manager/state.txt (NOT session/wraith_body.txt)
  - Reads that via ${window_geom_display} variable substitution
  - This is the "mega-variable" pattern that's known problematic

For editable version, per 2do-july5.txt:
  - Switch to writing session/wraith_body.txt directly
  - Use plain lines + <button> markup
  - Same output path every other Window project uses
  - Deletes the mega-variable problem by reusing proven path
