## EXECUTIVE SUMMARY

**Goal:** Make piececraft-wraith a fully playable, responsive 2D/3D game inside Wraith that mirrors piececraft-3d functionality while following TPMOS standards.

**MVP Scope:** Phases 1-2 (basic playability, Z-levels, mode switching)
**Timeline:** 2-3 weeks (assuming 4-6 hours/day)
**Success Criteria:** Responsive map control, xelector movement, Z-level switching, 2D/3D toggle

## PHASE 1: FOUNDATIONAL ARCHITECTURE & BASIC PLAYABILITY

**Goal:** Make piececraft-wraith respond to input and display moving xelector

**Duration:** 3-4 days
**Deliverables:** Playable MVP with responsive map and working xelector movement

### Phase 1 Steps:

#### Step 1.1: Create Manager Daemon
**Files to create:**
- `projects/wraith-alpha/wraith-projects/piececraft-wraith/manager/piececraft-wraith_manager.c`
- `projects/wraith-alpha/wraith-projects/piececraft-wraith/manager/+x/piececraft-wraith_manager.+x` (compiled binary)

**Tasks:**
1. Copy structure from `projects/fuzz-op/manager/fuzz-op_manager.c`
2. Adapt for Wraith paths (session/history.txt instead of pieces/apps/player_app/history.txt)
3. Implement core functions:
   - `resolve_paths()` - find project root and session directory
   - `input_thread()` - monitor session/history.txt for new input
   - `route_input(int key)` - main input handler
   - `save_manager_state()` - write to session/state.txt
   - `trigger_render()` - poke render markers
4. Implement key handlers:
   - Arrow keys (1000-1003) → move xelector
   - 'x' / 'X' (120/88) → increment pos_z
   - 'z' / 'Z' (122/90) → decrement pos_z
   - ESC (27) → return to menu
   - '8' (56) → toggle display_mode (deferred to Phase 2)
5. Call render_map op after each input
6. Compile and test binary generation

**KPIs:**
- ✓ Manager compiles without errors
- ✓ Manager detects new history entries
- ✓ Key codes are correctly interpreted
- ✓ state.txt is updated after input

**Testing:**
```bash
# Manual test: append to session/history.txt and check state updates
echo "[Sat Jul  2 04:00:00 2026] KEY_PRESSED: 1003" >> session/history.txt
# Verify pos_y incremented in session/state.txt
```

   ```
   cam_yaw=0.0

   ```

**KPIs:**

## DOCUMENTATION & CODE STANDARDS

### Coding Standards (from TPMOS bible)
- No shared `.h` files; each `.c` is self-contained
- Use `asprintf` for all path construction
- Register `SIGINT`/`SIGTERM` handlers
- Use `fork()/exec()/waitpid()` for child processes
- Prefer marker files over `stat()` polling
- No `system()` calls; use `fork()/exec()` instead
- `setpgid(0, 0)` in main() for process group

### File Naming Conventions
- Managers: `{project}_manager.c`
- Ops: `{op_name}.c`
- Binaries: `{name}.+x`
- State files: `.../state.txt`
- Layout files: `layouts/{name}.chtpm` or `.gltpm`

### Comments & Documentation
- No multi-line docstrings
- One-line comments only for non-obvious WHY logic
- Assume readers understand the code
- Document architectural decisions (not implementation)
