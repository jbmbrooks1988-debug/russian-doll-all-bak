================================================================================
HOW WRAITH ACTUALLY WORKS
================================================================================

Wraith Window Display Pipeline:

1. User selects project in Wraith
2. wraith-alpha_manager detects it
3. Launches project's manager via fork()/execl()
4. Manager runs and writes to session/wraith_body.txt
5. Wraith parser reads wraith_body.txt
6. Wraith renders it in the window
7. Done!

That's it. No variables, no substitution, no complex state projection.
Just write content to wraith_body.txt and it appears in the window.

================================================================================
ARCHITECTURAL LESSON LEARNED
================================================================================

PATTERN: Wraith-Hosted Interactive Project

Structure:
  projects/wraith-alpha/wraith-projects/[PROJECT_NAME]/
  ├── project.pdl (declares: manager = path/to/manager)
  ├── manager/
  │   ├── [PROJECT]_manager.c (reads input, updates state)
  │   └── +x/[PROJECT]_manager.+x (compiled binary)
  ├── layouts/
  │   └── [PROJECT].chtpm (window structure, non-dynamic)
  └── session/
      ├── history.txt (input from Wraith)
      └── wraith_body.txt (content to display)

Execution:
  1. User selects project in Wraith
  2. wraith-alpha_manager.c detects it
  3. Spawns [PROJECT]_manager.c as child process
  4. [PROJECT]_manager reads history.txt for input
  5. [PROJECT]_manager outputs to wraith_body.txt
  6. Wraith reads wraith_body.txt
  7. Window displays updated content

This is PURE TPMOS: state files, manager daemons, ops, input history.
No GUI frameworks, no variable substitution, no hidden dependencies.
Just processes, files, and a clear data flow.
