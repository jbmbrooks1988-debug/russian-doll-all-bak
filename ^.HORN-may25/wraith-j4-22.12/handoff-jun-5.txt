2. PRODUCT UNDERSTANDING TO PRESERVE
==================================================

Wraith is:

- an ASCII desktop/window-manager environment
- behaviorally inspired by GL-OS
- file-backed and inspectable like TPMOS
- new as a desktop/runtime shell
- not new as a random app standard

Important distinction:

- Wraith may contain its own subprojects under:
  `projects/wraith-pm/wraith-projects/`
- but those subprojects should still follow TPMOS-style `.pdl` loading and
  existing standards

Core native ownership model from blueprint:

- `wraith_parser` should own live input semantics
- manager should own canonical desktop/window state and lifecycle
- composer should render canonical truth only

Do NOT regress back to:

- fake pre-opened windows
- split-brain focus/nav ownership
- manager behaving like a second hidden parser
- mouse spam as a substitute for real interaction architecture

5. WHAT WAS FIXED IN THIS RUN
==================================================

There were two meaningful fixes in this run.


--------------------------------------------------
5A. BOOT NORMALIZATION / STATE OWNERSHIP
--------------------------------------------------

File changed:

- `projects/wraith-pm/manager/wraith-pm_manager.c`

What was done:

- Boot now normalizes to terminal-only startup.
- Boot now resets:
  - `focused_window=terminal_window`
  - `open_game_map_window=false`
  - `open_blank_proj_window=false`
  - `selected_index=1`
  - `nav_scope=terminal_menu`
- Focus and nav scope are now updated together through
  `set_focus_and_scope(...)`.
- `focus map` does not activate unless `game-map` is actually open.

Why it mattered:

Before this, Wraith could boot into contradictory truth such as:

- `focused_window=game_map_window`
- `nav_scope=terminal_menu`
- visible frame only showing terminal

That contradiction was removed for baseline boot.


--------------------------------------------------
5B. PARSER STALE-HISTORY REPLAY BUG
--------------------------------------------------

File changed:

- `projects/wraith-pm/ops/wraith_parser.c`

Exact fix:

At parser startup, it now sets:

- `last_history_position = size_of(pieces/keyboard/history.txt)`

before entering the input loop.

What bug this fixed:

Before this, launching `wraith_parser` could replay old keyboard history from
earlier runs. That caused stale `Enter`, arrows, and other keys to fire again.

Practical bad symptom:

- `blank-proj` could reopen unexpectedly
- `game-map` could open alongside it
- parser-driven tests were polluted by old key history

Why this was a real bug:

It made end-to-end nav/open behavior look nondeterministic when the real cause
was stale input replay.
