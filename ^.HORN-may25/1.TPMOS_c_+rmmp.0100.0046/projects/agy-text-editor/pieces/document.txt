# Investigation: Load Project Bug (m24)

## 1. Symptom
Selecting a file in the browser (e.g., `hi.txt`) fails to update the `ACTIVE` project variable in the UI, and the response line remains stuck at "Select file to load." instead of showing "Loaded ...".

## 2. Root Cause Discovery: The Stale Path Mandate
The `agy-text-editor_manager.c` strictly adheres to the TPMOS Bible by resolving `project_root` from `pieces/locations/location_kvp`.
Current value in `location_kvp`:
`project_root=/home/no/Desktop/🚽️/!.EXOTOY-00.00/File-Op-Ed/1.TPMOS_c_+rmmp.0100.0000`

This path is **STALE** and does not exist in the current environment (`/home/debilu/.../0100.0001`).

### Impact on LOAD
When `LOAD_FILE:projects/agy-text-editor/hi.txt` is triggered:
1. `load_from_path` resolves the path using the stale `project_root`.
2. `fopen()` fails to find the file in the non-existent directory.
3. The function returns -1 without updating `active_file_path`.
4. `update_gui_state()` is called, but it writes the OLD `active_file_path` ("document.txt") back to `gui_state.txt`.

### Impact on SAVE (Why it "Works")
When `SAVE_AS_ACTION` is triggered:
1. It reads the local `document.txt` (if `project_root` is relative, but here it's absolute).
2. It attempts to write to the stale path.
3. **Observation:** If the parent directories exist in the stale path (unlikely), it writes there. If not, it fails.
4. **Conclusion:** Save only "works" if the path resolution falls back to something valid or if the user is misled by a successful return code from a previous session's artifact.

## 3. Comparison with Working Solution
The "working" state observed in `gui_state.txt` (e.g., `active_project=projects/agy-text-editor/hi-4`) occurred during a turn where `active_file_path` was updated by a command that successfully bypassed or correctly resolved the path.

## 4. Proposed Fix
The Manager must be resilient to stale system-wide configuration. It should:
1. Validate the `project_root` resolved from `location_kvp`.
2. Fall back to `.` if the resolved path is invalid or non-existent.
3. Ensure all file operations (`fopen`, `stat`) use this validated root.

## 5. Secondary Bug: Key Collision
Numeric keys ('1'-'9') were being intercepted by the global command handler even in the browser. This has been partially addressed but relies on successful layout name resolution, which also depends on `project_root`.
