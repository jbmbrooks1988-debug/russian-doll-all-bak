THE THEORY
==========

After full element processing was added, the most likely cause is that
the href navigation is blocked by one of these:

A. HREF ATTRIBUTE NOT BEING SET
   - parse_attributes() is called, but maybe href isn't in st->attributes
   - Or substitution replaced the href with empty string
   - Check: is el->href actually populated for these buttons?

B. NAVIGATION BLOCKED BY ACTIVATE MENU LOGIC
   - When an ACTIVATE button is open (active_index set), navigation might be blocked
   - Check: does is_navigable() return false for buttons inside active ACTIVATE?
   - Check: does the href handler in handle_key_input() check navigability?

C. INTERACTION/DISPATCH ISSUE
   - Button is recognized (it has a number, gets rendered)
   - But when clicked/selected, dispatch doesn't recognize href
   - Check: in handle_key_input(), does the href branch get reached?
   - Check: does the code differentiate between href inside vs outside ACTIVATE?

D. CLICK TARGET MISMATCH
   - The button is rendered at one position in the frame
   - But the hit-zone calculation is wrong due to indentation
   - Check: hit_zones array for these buttons
   - Check: indentation logic doesn't mess up coordinates
