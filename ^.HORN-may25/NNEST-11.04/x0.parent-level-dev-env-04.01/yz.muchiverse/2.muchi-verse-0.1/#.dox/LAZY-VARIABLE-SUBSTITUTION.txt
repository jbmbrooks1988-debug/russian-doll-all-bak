LAZY VARIABLE SUBSTITUTION FOR XML-GENERATING VARIABLES
=========================================================
Date: 2026-07-22
Context: piece_methods_compact needs to generate nested elements inside ACTIVATE buttons

PROBLEM
=======
Current flow:
  1. substitute_vars_naked() replaces ${piece_methods_compact} with XML string
  2. tokenize() processes the whole layout
  3. Parser builds element tree via stack

Issue: XML generated by substitution gets treated as TEXT, not as real elements
Result: piece_methods buttons don't have correct parent_index (Actions button)

SOLUTION: LAZY SUBSTITUTION DURING PARSE
=========================================

Move substitution into the parse loop. When building elements:

1. Encounter a TEXT token with "${var}" in it
2. Call substitute_vars() on that text
3. Check if result is XML-like (contains "<" and ">")
4. If XML:
   a. Tokenize the substituted content
   b. Re-enter parse loop for those tokens
   c. Stack tracking continues (parent_index set correctly)
5. If plain text:
   a. Create a TEXT element normally

Pseudocode in parse_chtm():

  for (int i = 0; i < tc && element_count < MAX_ELEMENTS; i++) {
      Token* t = &tokens[i];

      if (t->type == TOKEN_TEXT) {
          // NEW: Check if text contains variables that expand to XML
          char substituted[MAX_BUFFER];
          substitute_vars(t->content, substituted, MAX_BUFFER);

          if (substituted contains "<") {
              // This text expanded to XML - parse it as elements
              int sub_tc;
              Token* sub_tokens = tokenize(substituted, &sub_tc);

              // Inject sub_tokens into the main token stream at position i+1
              // Continue parsing with updated token list
              // Stack management continues seamlessly

              free(sub_tokens);
          } else {
              // Plain text - create TEXT element normally
              create_text_element(substituted);
          }
      } else if (t->type == TOKEN_OPEN_TAG || ...) {
          // Regular tag parsing (unchanged)
      }
  }

BENEFITS
========
✅ Self-contained: variable handling in one place
✅ Modular: any future XML-generating variable works automatically
✅ Surgical: minimal change to existing parse loop
✅ Scalable: no parser rewrites needed for new dynamic content
✅ Discipline-aligned: fits "one job per component" pattern

IMPLEMENTATION DETAILS
======================

1. Add helper function: is_xml_like(const char* str)
   - Returns true if string contains "<" followed by valid tag name
   - Prevents false positives on plain text with angle brackets

2. Modify parse_chtm() token loop (around line 2335-2340)
   - After creating TEXT element, check if text was substituted from variable
   - If is_xml_like(), tokenize and inject

3. Token injection strategy:
   Option A: Rebuild token array with injected tokens (complex, memory-heavy)
   Option B: Recursive parse call for substituted content (simpler)
   Option C: Use a token queue/stack (most flexible)

   RECOMMENDATION: Option B (recursive)
   - Reuse existing parse logic
   - Stack management automatic
   - Minimal code change

EDGE CASES
==========
- Variable contains XML that's incomplete (unclosed tags)
  → Tokenizer will handle gracefully, elements will have parent_index from stack

- Variable contains multiple elements (most common - piece_methods_compact)
  → Multiple elements parse as siblings, all with same parent_index

- Nested variables (${var1} contains ${var2})
  → First substitution handles var1, if result contains var2, re-substitute
  → May need recursive substitute_vars() call

- Variable value contains literal "<" that's not XML
  → is_xml_like() check prevents false parsing
