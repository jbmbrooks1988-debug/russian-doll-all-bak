2. Core understanding to preserve

Wraith is:

- a new desktop/window-manager environment
- rendered in ASCII
- behaviorally inspired by GL-OS
- file-backed and inspectable like TPMOS

Wraith is NOT:

- a replacement app standard
- a fake demo desktop with pre-opened windows
- a one-off special loader that ignores TPMOS project structure

Important distinction:

- Wraith can contain its own subprojects under
  `projects/wraith-pm/wraith-projects/`
- that part is new
- but those subprojects should still use the same TPMOS-style `.pdl` loading
  model and the same core standards/data structures
- the difference is the GUI/runtime shell, not a new project standard


3. Current intended behavior

Startup:

- Wraith should start in shell/desktop mode
- for now, open one default terminal window for convenience/dev
- do not auto-open `game-map`
- do not treat presence of a content file as proof that a window is open

Opening projects:

- the game menu is itself a project
- additional Wraith projects may exist as subdirs in
  `projects/wraith-pm/wraith-projects/`
- selection from the launcher/menu should open a new window for that project
- project loading should resolve from the subproject's `.pdl`, not from a
  hardcoded special case

Focus and nav:

- the focused window must own the active selector/nav
- if terminal is focused, terminal menu/nav is active
- if game-map is focused, game-map selector/nav is active
- no split-brain state where desktop focus says one thing and nav state says
  another


4. What was already fixed

- Composer no longer renders a hardcoded `96x30` fake full desktop.
- Frame sizing now follows actual visible windows/taskbar bounds.
- The header no longer forces the huge `MOUSE:` debug row width.
- The taskbar no longer collides with the clock in the shrunken frame.
- Wraith is confirmed to use `wraith_parser`, not `chtpm_parser`.
- The manager and composer were moved toward a canonical
  `session/windows_state.pdl` registry.

Observed current persisted state:

That is wrong according to the blueprint.
