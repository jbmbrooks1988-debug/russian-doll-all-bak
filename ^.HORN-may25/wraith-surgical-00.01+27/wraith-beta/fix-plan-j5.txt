# FINAL REMEDIATION PLAN: WRAITH NAVIGATION STALL (fix-plan-j5.txt)
Date: 2026-06-05

This plan addresses the three root causes identified in `code-rev-j5.txt` to align Wraith with TPMOS standards and achieve runtime honesty.

## 1. Absolute Parser Read-Integrity (Fixing Stale Cache)
*   **The Issue:** The Parser's `vars[]` cache is persistent across marker pulses, leading to stale data.
*   **The Fix:**
    1.  Refactor `reload_live_layout_state` to explicitly `memset(vars, 0, sizeof(vars))` and set `var_count = 0` at the very *beginning* of the pulse.
    2.  Add diagnostic `fprintf(stderr, ...)` in `load_vars` to print every key/value pair loaded from `nav_state.txt` and `gui_state.txt`. This will prove if we are reading the updated index or not.

## 2. Decommissioning the Compositor (Eliminating Race Conditions)
*   **The Issue:** The `wraith_composer` is a redundant, racing process that violates "one-owner" standards.
*   **The Fix:**
    1.  Identify all calls to `trigger_render` in `wraith-pm_manager.c`.
    2.  Remove the `fork()` and `exec()` call to `wraith_composer.+x`.
    3.  Keep the `trigger_render` function only to pulse `pieces/display/frame_changed.txt`.
    4.  Verify that the `Parser` alone can handle all visual composition using the updated state files.

## 3. Auditing State Propagation (Fixing Logic Gaps)
*   **The Issue:** `history_thread` depends on `batch_changed` to trigger `sync_nav_state`.
*   **The Fix:**
    1.  Modify `route_input` in `wraith-pm_manager.c` to explicitly return `changed = 1` for *any* key press that *could* affect navigation (e.g., UP, DOWN, ENTER, digit).
    2.  Ensure that *whenever* `route_input` returns 1, the `history_thread` *immediately* proceeds to `sync_nav_state`, `update_terminal_view`, `update_gui_state`, and `trigger_render`.
    3.  Remove all conditional gating (`batch_changed`) that might delay state propagation.
