2. Remaining Mysteries (Why is it still doing it?)

Mystery A: The "Two Identical Pulses" Paradox
If the dual-hash fingerprint check is active, the Parser should ONLY pulse
renderer_pulse.txt if the frame string has changed. If the user sees two
identical frames at the same timestamp, it means:
- EITHER: Something in the frame string is changing invisibly (e.g. whitespace,
  hidden frame IDs, or trailing control chars).
- OR: There is more than one Parser process running, or a background process
  is bypassing the Parser's logic.

Mystery B: The "Stale Clock" Phenomenon
User sees "13:26" in the header, but the taskbar says "13:24".
- This means the Parser composed at 13:26, but the variables it loaded from
  state.txt were 2 minutes old.
- Possible Cause: The Manager process died or hang, or its clock-sync thread
  is blocked.

Mystery C: Process Interference
I have manually launched background parsers multiple times. If an old version
of the parser (without the fingerprint check) is still alive in a detached
process group, it will keep pulsing markers unconditionally.
