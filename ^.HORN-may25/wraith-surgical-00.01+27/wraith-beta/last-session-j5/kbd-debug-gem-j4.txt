WRAITH KEYBOARD DEBUG PRESCRIPTION
Date: 2026-06-05

Purpose:
To fix the stale "K:" label and inconsistent keyboard feedback in Wraith by
aligning with the working TPMOS "One Truth" pattern found in fuzz-op.


Findings:

1. Split-Brain Key Polling:
   - wraith-pm_manager.c correctly reads from pieces/apps/player_app/history.txt
     and updates current_key in projects/wraith-pm/session/state.txt.
   - HOWEVER, wraith_composer.c (run by the manager) had a function
     load_latest_keyboard_key() that polled pieces/keyboard/history.txt and
     OVERWROTE the current_key value.
   - This caused the UI to show the last key from the GLOBAL history instead
     of the last key processed by the Wraith Manager.

2. Stale Global History:
   - The global keyboard history is not always in sync with the app-specific
     history used for navigation.
   - This is why simulations using player_app/history.txt updated the manager
     logic but not the visible "K:" label.


Prescription:

1. Fix wraith_composer.c:
   - DELETED the load_latest_keyboard_key() function.
   - Removed the call to load_latest_keyboard_key() in load_desktop_state().
   - This ensures the composer trusts the Manager's state file (state.txt)
     as the singular source of truth for the displayed key.

2. Verify wraith_parser.c sync:
   - Ensure the parser reloads variables from state.txt on every display pulse.
     (Already addressed by updating load_vars() to include Wraith session files).

3. Standard Alignment:
   - Follow the fuzz-op pattern where the manager owns the "last_key" state
     and the renderer simply reflects that state.


Expected Outcome:
- The "K:" label in the taskbar will match the key that actually moved the
  selector.
- Simulating keys in player_app/history.txt will correctly update both the
  navigation state and the visible debug label.
