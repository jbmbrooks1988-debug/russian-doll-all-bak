Fuzz-Op Bug Report (j10)
=======================
Date: 2026-06-10
Issues: Zombie movement failed, Hotkeys failed.

1. Zombie Movement Failure
---------------------------
- Symptom: Zombie appears on the map but does not chase the player.
- Root Cause: 'zombie_ai.c' and 'move_entity.c' use hardcoded flat pathing (projects/fuzz-op/pieces/<id>/state.txt). However, the zombie (zombie_01) and other entities (pet_01, pet_02) are located in nested canonical paths (projects/fuzz-op/pieces/world_01/map_01/<id>/state.txt).
- Evidence: 'render_map.c' uses recursive directory scanning to find entities, which is why they appear on the map. 'zombie_ai.c' and 'move_entity.c' fail to find the state.txt files and exit silently or return -1.
- Pitfall Reference: #1 (WORLD/MAP PATHING DRIFT) - "Canonical path is: projects/<project>/pieces/world_<id>/map_<id>/<piece_id>/"

2. Hotkeys Failure
------------------
- Symptom: Pressing 2-9 does not trigger PDL methods (scan, feed, etc.).
- Root Cause: 'fuzz-op_manager.c' incorrectly quotes the entire command string (including arguments) when calling system(). 
- Evidence: asprintf(&quoted_handler, "'%s/%s'", project_root, handler); where handler contains arguments (e.g., "bin/op arg"). This results in system("'path/to/bin arg'"), which the shell interprets as a single file name rather than a command with arguments.
- Secondary Issue: 'pdl_reader.c' also uses flat pathing, preventing it from finding methods for nested entities (though it works for 'xlector' which is in the root pieces dir).

Fix Strategy
------------
1. Update 'zombie_ai.c' and 'move_entity.c' to use recursive path resolution (find_piece_state_recursive) similar to the manager and 'render_map.c'.
2. Update 'fuzz-op_manager.c' to only quote the project_root part of the path, or handle arguments separately.
3. Recompile affected binaries.
