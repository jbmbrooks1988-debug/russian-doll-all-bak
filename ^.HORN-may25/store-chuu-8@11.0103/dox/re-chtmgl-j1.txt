# Technical Specification: Tree-Based Hierarchical Rendering for CHTMGL
**Status:** ARCHITECTURAL PROPOSAL (Refactor J1)
**Objective:** Replace manual relative coordinate math with a robust hierarchical transformation stack to ensure sub-windows and nested UI components are correctly contained and rendered.

---

## 1. The Core Shift: From Manual Math to Matrix Stack
The previous implementation relied on manual calculation of child element offsets based on parent positions. This approach was error-prone, particularly with nested containers (`panel > div > button`).

**New Approach:**
- Utilize OpenGL’s built-in `glPushMatrix()` and `glPopMatrix()` during scene graph traversal.
- Each container (Panel, Div) becomes a node in a tree.
- When traversing into a container:
  1. Save current state (`glPushMatrix`).
  2. Apply transformation (`glTranslatef`).
  3. Render children (relative to local 0,0).
  4. Restore previous state (`glPopMatrix`).

## 2. Hierarchical Clipping (Scissor-Based)
Clipping must be enforced at the container boundary to prevent elements from "escaping" their parents.

**Implementation Strategy:**
- Each container defines a bounding box (x, y, w, h).
- Before rendering children of a container, calculate the intersection of the container's box and the parent's current scissor box.
- Apply the intersected rectangle using `glScissor()`.
- Restore the parent's scissor box upon popping the stack.
- This guarantees that no child element can ever render outside its immediate parent's defined container area.

## 3. Tree Traversal Algorithm
The parser and renderer should be unified into a recursive visitor pattern:

```c
void render_node(Node* node) {
    glPushMatrix();
    glTranslatef(node->x, node->y, 0);

    // 1. Clip to container bounds
    apply_scissor_clipping(node);

    // 2. Render children
    for (Child in node->children) {
        if (Child->type == BUTTON) render_button(Child);
        else if (Child->type == CONTAINER) render_node(Child);
    }

    // 3. Cleanup
    restore_previous_clipping();
    glPopMatrix();
}
```

## 4. Key Benefits
1. **Coordinate Isolation:** Errors in a specific container's position do not propagate to sibling branches.
2. **Simplified Logic:** No need for complex cumulative offset tracking (`cur_offset_x`, `cur_offset_y`).
3. **Robustness:** Scissor clipping is now structurally bound to the tree traversal, ensuring children strictly respect parent containers.
