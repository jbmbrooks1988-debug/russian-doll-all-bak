## 2. Addressing Specific Concerns

### Concern #1: Data-Driven Map (Canvas Pattern)
- **Current Deviation:** The layout currently hardcodes entity positions.
- **CHTPM Standard:** The parser processes `${game_map}` as a text block, and a `canvas_process` function translates characters into objects.
- **Refactor Plan:**
    1. Introduce `gltpm_process_canvas_block` in `gltpm_parser.c`.
    2. Maintain `canvas_row_offset` across multi-line parsing calls.
    3. Look up characters in `projects/<id>/assets/tiles/registry.txt`.
    4. Map characters to 3D tiles using `.tile.txt` metadata for extrusion/color.

### Concern #2: Menu Rendering Order
- **Current Deviation:** Reverse Y-order (1 is at bottom).
- **CHTPM Standard:** Linear top-down list.
- **Refactor Plan:**
    1. In `gl_desktop.c`, invert the rendering loop: draw from index 0 (Top) down to index N-1 (Bottom).
    2. Ensure `selected_index` maps linearly to this new loop.

### Concern #3: Interact Mode ('Enter' Key)
- **Current Deviation:** Hardcoded toggles.
- **CHTPM Standard:** Parser discovers `<interact src="...">`. When the user triggers an `onClick` on that element, the parser yields to the manager, and the host enters "Relay Mode" (routing all inputs to `history.txt`).
- **Refactor Plan:** 
    1. Add `interact_src` to `GLTPMScene` struct.
    2. Parser sets `win->is_map_control = 1` only upon successfully triggering an element with an `<interact>` attribute.
