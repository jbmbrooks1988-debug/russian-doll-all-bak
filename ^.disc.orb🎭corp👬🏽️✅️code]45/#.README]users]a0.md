# Discord Bot System

This document outlines the Discord bot system, its recent updates, and how developers can leverage the new user ID functionality in modules like `games.c` to add personalized features.

## Overview
The bot is a modular C program that interacts with the Discord API via WebSocket to process commands and respond in specified channels. It consists of three main components:
- **`receive.c`**: Connects to Discord’s WebSocket gateway, receives messages, and writes them to `events.txt`.
- **`users.c`**: Processes user-related commands (e.g., `!user`) and tracks user state.
- **`games.c`**: Handles game-related commands (e.g., `!hi`, `!test`, `!sos`) and sends responses.

The system uses files for inter-process communication:
- `events.txt`: Stores incoming messages in the format `channel_id|timestamp|hash|content`.
- `send_queue.txt`: Stores outgoing messages for `send.c` to process.
- `users_processed_hashes.txt` and `processed_hashes.txt`: Track processed events for `users.c` and `games.c`, respectively.
- `users/`: Stores per-user state files (e.g., `123456789012345678.state.txt`).
- `sos.txt`: Contains help text for the `!sos` command.

## Recent Updates
The bot was recently updated to improve user identification and enable user-specific functionality:
1. **User ID Prefix in `events.txt`**:
   - `receive.c` now prepends `<@user_id>` to the `content` field in `events.txt` for all `MESSAGE_CREATE` events (e.g., `840391516689137687|1754596763|xxxxxx|<@123456789012345678> !hi`).
   - This allows modules to extract the Discord user ID (`123456789012345678`) for personalized responses or state tracking.
   - The change ensures commands like `!user` are associated with specific users, fixing issues where user identification failed due to missing or malformed fields in Discord payloads.

2. **Robust Parsing in `receive.c`**:
   - `receive.c` now handles Discord’s JSON payloads more reliably, extracting `content`, `channel_id`, and `author.id` individually and logging specific parsing errors (e.g., “Missing author_id in payload”).
   - Messages are written to `events.txt` even if some fields are missing, as long as `channel_id` and either `content` or `author_id` are valid.

3. **Enhanced `users.c`**:
   - Processes `!user` commands with the format `<@user_id> !user`, extracting the user ID and updating per-user state files in `users/`.
   - Sends responses like `User 123456789012345678 state: user_command_count=1 last_login=1754596763`.
   - Includes improved logging and hash deduplication to prevent reprocessing events.

4. **Updated `games.c`** (Optional, as old version may still work):

## Using User IDs for Enhanced Functionality
The `<@user_id>` prefix in `events.txt` enables developers to add user-specific features to modules like `games.c`. Below are steps to leverage this in new or existing modules.

### Extracting User ID and Command
The `content` field in `events.txt` now has the format `<@user_id> command` (e.g., `<@123456789012345678> !hi`). To process this:
1. **Check for Prefix**:
   - Look for `<@` at the start and `> ` before the command:
     ```c
     char* cmd_start = strstr(content, "> ");
     char* cmd = cmd_start ? cmd_start + 2 : content;
     ```
2. **Extract User ID**:
   - If `<@` is present, extract the user ID between `<@` and `>`:
     ```c
     char user_id[32] = {0};
     if (cmd_start && strncmp(content, "<@", 2) == 0) {
         char* user_id_start = content + 2;
         char* user_id_end = strchr(user_id_start, '>');
         if (user_id_end) {
             int user_id_len = user_id_end - user_id_start;
             if (user_id_len < sizeof(user_id)) {
                 strncpy(user_id, user_id_start, user_id_len);
                 user_id[user_id_len] = '\0';
             }
         }
     }
     ```
3. **Process Command**:
   - Use `cmd` to check for commands (e.g., `strcmp(cmd, "!hi")`) and `user_id` for personalized logic or state tracking.

    unsigned int hash = 0;

void send_websocket_frame(SSL* ssl, const char* payload) {
    size_t len = strlen(payload);
    if (len >= MAX_PAYLOAD_SIZE - 8) { log_message("Payload too large"); return; }
    unsigned char frame[MAX_PAYLOAD_SIZE];
    frame[0] = 0x81;
    int offset;
    unsigned char mask_key[4];
    RAND_bytes(mask_key, 4);

    if (len < 126) {
        frame[1] = 0x80 | len;
        offset = 2;
    } else {
        frame[1] = 0x80 | 126;
        frame[2] = (len >> 8) & 0xFF;
        frame[3] = len & 0xFF;
        offset = 4;
    }

    memcpy(frame + offset, mask_key, 4);
    offset += 4;
    for (size_t i = 0; i < len; i++) {
        frame[offset + i] = payload[i] ^ mask_key[i % 4];
    }

    int frame_len = offset + len;
    int written = SSL_write(ssl, frame, frame_len);
    char log[256];
    if (written <= 0) {
        snprintf(log, sizeof(log), "Failed to send frame: %d", SSL_get_error(ssl, written));
        log_message(log);
    } else {
        snprintf(log, sizeof(log), "Sent: %s", payload);
        log_message(log);
    }
}

int connect_websocket(SSL** ssl, SSL_CTX* ctx, int* sock, char* session_id, int sequence) {
    *sock = socket(AF_INET, SOCK_STREAM, 0);
    if (*sock < 0) {
        log_message("Socket creation failed");
        return 0;
    }
    int flags = fcntl(*sock, F_GETFL, 0);
    fcntl(*sock, F_SETFL, flags | O_NONBLOCK);

    struct hostent* he = gethostbyname(HOST);
    struct sockaddr_in addr = { .sin_family = AF_INET, .sin_port = htons(PORT) };
    memcpy(&addr.sin_addr, he->h_addr_list[0], he->h_length);

    if (connect(*sock, (struct sockaddr*)&addr, sizeof(addr)) < 0 && errno != EINPROGRESS) {
        log_message("Connection failed");
        close(*sock);
        return 0;
    }

    fd_set write_fds;
    struct timeval tv = { .tv_sec = 5, .tv_usec = 0 };
    FD_ZERO(&write_fds);
    FD_SET(*sock, &write_fds);
    if (select(*sock + 1, NULL, &write_fds, NULL, &tv) <= 0) {
        log_message("Connection timed out");
        close(*sock);
        return 0;
    }

    fcntl(*sock, F_SETFL, flags & ~O_NONBLOCK);

    *ssl = SSL_new(ctx);
    SSL_set_fd(*ssl, *sock);
    SSL_set_tlsext_host_name(*ssl, HOST);
    if (SSL_connect(*ssl) <= 0) {
        log_message("SSL handshake failed");
        close(*sock);
        return 0;
    }

    SSL_set_mode(*ssl, SSL_MODE_AUTO_RETRY);
    flags = fcntl(*sock, F_GETFL, 0);
